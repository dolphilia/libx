<a id="source-entropy-encoding"></a>

エントロピー符号化
----------------
Zstandard形式では、FSEとHuffman符号化という2種類のエントロピー符号化を使います。
Huffmanはリテラルの圧縮に使い、FSEはその他すべてのシンボル
（`Literals_Length_Code`、`Match_Length_Code`、オフセットコード）と、Huffmanヘッダーの圧縮に使います。

<a id="source-fse"></a>

FSE
---
FSEはFinite State Entropyの略で、[ANS]に基づくエントロピーコーデックです。
FSEの符号化・復号では、シンボル間で引き継ぐ状態を使います。
復号は符号化と逆の方向に行う必要があります。そのため、すべてのFSEビットストリームは末尾から先頭へ読みます。
ストリーム内のビット順を逆転させるのではなく、複数ビットからなる各要素を、符号化した順序と逆順に読むだけである点に注意してください。

FSEの詳細は[Finite State Entropy]を参照してください。

[Finite State Entropy]:https://github.com/Cyan4973/FiniteStateEntropy/

FSEの復号は、サイズが2の累乗である復号表に従います。各行は`Symbol`、`Num_Bits`、`Baseline`の3要素を含みます。
表のサイズの`log2`が`Accuracy_Log`です。FSE状態値は、この表のインデックスを表します。

初期状態値を取得するには、ストリームから`Accuracy_Log`ビットを**リトルエンディアン**値として消費します。
ストリームの最初のシンボルは、その状態に対応する表の`Symbol`です。
次の状態値を取得するには、デコーダーはストリームから`Num_Bits`ビットを**リトルエンディアン**値として消費し、`Baseline`に加算する必要があります。

[ANS]: https://en.wikipedia.org/wiki/Asymmetric_Numeral_Systems

<a id="source-fse-table-description"></a>

### FSE表の記述
FSEビットストリームを復号するには、FSE復号表を構築する必要があります。
復号表は確率分布から導きます。Zstandard形式は、確率分布を次のように符号化します。

確率分布は、**リトルエンディアン**で順方向に読むビットストリームによって記述します。
分布の記述に消費したバイト数は、復号処理の終了時に判明します。

ビットストリームの先頭では、分布の尺度を通知します。
最初のバイトの下位4ビットを`low4Bits`とすると、`Accuracy_Log = low4bits + 5`です。

FSE分布表は、`0`から最後に存在するシンボルまで（両端を含む）、すべてのシンボルの確率を自然順で記述します。
確率の合計は、2の累乗である`1 << Accuracy_Log`になるように正規化します。
確率がゼロでないシンボルが、2つ以上存在しなければなりません。

各確率の復号に使うビット数は可変で、次の要素によって決まります:

- 残りの確率の合計 + 1:
  __例__: `Accuracy_Log`が8で、100個の確率ポイントがすでに割り当てられているとします。
  デコーダーは、`0`から`256 - 100 + 1 == 157`まで（両端を含む）の任意の値を読み取れます。
  したがって、最大で`log2sup(157) == 8`ビットを読み取れます。
  ここで`log2sup(N)`は、`(1 << T) > N`を満たす最小の整数`T`です。

- 復号する値: 小さい値は1ビット少なくなります。
  __例__: 0から157まで（両端を含む）の値を取れる場合、8ビットのフィールドには255-157 = 98個の値が余ります。
  これを次のように利用します。最初の98個の値（0から97）は7ビットだけを使い、98から157は8ビットを使います。
  次の方式で実現します:

  | 読み取った8ビットフィールド | 復号値 | 消費ビット数 |
  | ---------------- | ------------- | ------------------- |
  |         0 -  97  |   0 -  97     |  7                  |
  |        98 - 127  |  98 - 127     |  8                  |
  |       128 - 225  |   0 -  97     |  7                  |
  |       226 - 255  | 128 - 157     |  8                  |

確率は、復号した値から次の式で導きます: `Probality = Value - 1`

したがって、確率`0`は値`1`で記述します。

値`0`は、「確率`-1`」と呼ぶ特殊なケースを示すために使います。
これは「1未満」であるはずの確率を表します。
復号表の構築への影響は[次の節][next section]で説明します。
割り当て済み確率ポイントの合計を数える際には、1として数えます。

[next section]:/docs/zstd/v1-5-7/ja/01-specification/06-fse#source-from-normalized-distribution-to-decoding-tables

シンボルの確率は、順番に1つずつ読み取ります。
各確率を復号するたびに、確率ポイントの合計を更新します。
この合計を使って、次のシンボルの確率を復号するために読むビット数を決めます。

シンボルの**確率**が`zero`（値`1`を読み取って復号したもの）の場合、後ろに2ビットの繰り返しフラグが続きます。
このフラグは、現在の確率の後に続く確率ゼロの個数を示し、0から3の値を取ります。
値が3の場合は、さらに別の2ビットの繰り返しフラグが続き、このように繰り返します。

あるシンボルの確率によって累計が`1 << Accuracy_Log`に達したら、そのシンボルが最後であり、復号は完了です。

この時点で、デコーダーは処理に使ったバイト数と、存在するシンボル数を判断できます。
ビットストリームは整数個のバイトを消費します。最後のバイトに残るビットは使いません。

この処理により、FSE表が定義されている有効なシンボル範囲の外にあるシンボルにゼロでない確率が与えられた場合、
そのシンボルを使っていなくても、データは破損していると見なします。
オフセットコードの場合には、デコーダー実装が対応する最大のオフセットコードを超えるコードにゼロでない確率があるフレームを、その実装が拒否してもかまいません。

<a id="source-from-normalized-distribution-to-decoding-tables"></a>

#### 正規化分布から復号表へ

正規化された確率分布だけで、一意の復号表を作成できます。次の構築規則を使って生成します:

表のサイズは`Table_Size = 1 << Accuracy_Log`です。
各行は、復号シンボルと、次の状態へ進むための指示（`Number_of_Bits`と`Baseline`）を指定します。

まず、自然順にシンボルを走査して「1未満」の確率（値`0`から復号したもの）を探します。
この特殊な確率を持つシンボルには、表の末尾から逆方向に1行ずつ割り当てます。
これらのシンボルは、`Accuracy_Log`ビットを読む、状態の完全なリセットを定義します。

次に、残るシンボルをすべて自然順に並べ、行を割り当てます。
存在する最小のシンボルと表の位置`0`から開始し、各シンボルにその確率と同数の行を割り当てます。

行の割り当ては線形ではなく、剰余演算による次の順序に従います:
```
position += (tableSize>>1) + (tableSize>>3) + 3;
position &= tableSize-1;
```

上の順序規則に従い、各シンボルにその確率と同数の行を割り当てます。
ある位置が「1未満」の確率のシンボルに占有されている場合は、その位置を飛ばし、代わりに次の位置を割り当てます。
現在のシンボルに十分な行を割り当てたら、自然順で次のシンボルに処理を続けます。
この処理により、表全体が過不足なく埋まることが保証されます。

各行は、復号シンボルを指定し、現在の状態値で参照します。
また、次の状態値を決めるために必要な`Number_of_Bits`と`Baseline`も指定します。

これらのフィールドを正しく設定するには、各シンボルが出現するすべての行を状態値の順に並べ、
下側の行にN+1ビット、上側の行にNビットを割り当てる必要があります。以下の手順で説明します（例を使用します）:

__例__:
`Accuracy_Log`が7で、あるシンボルの確率が5であるとします。
このシンボルは、`0`から`127`までの5つの状態値に対応する5行を受け取ります。

この例では、最初の状態値は（ここで指定していない先行シンボルの後の）`1`とします。
残り4つの状態は、上の剰余演算の規則で決めます。
次の位置へ移るために`64+16+3 = 83`を加え、`128`を法とするため、`1`、`84`、`39`、`122`、`77`という並びになります。
（次のシンボルは`32`から開始します。）

これらの状態値を自然順に並べると、`1`、`39`、`77`、`84`、`122`となります。

5の次の2の累乗は8です。そのため、確率空間を8等分します。
確率空間の大きさは`1<<7 = 128`なので、各部分の大きさは`128/8 = 16`です。

8つの部分に達するように、下位の`8-5 = 3`個の状態を「2倍」と数えます。
割り当てを2倍（幅32）にするため、1ビット多く必要になります。

Baselineは、より少ないビットを使う最小の状態から割り当て始め、状態値の自然順に進み、最後は先頭に戻ります。
各状態は、Baselineから始まり、その`Number_of_Bits`に応じた大きさの割り当て範囲を取ります。

| 状態の順番      |   0   |   1   |    2   |   3  |    4   |
| ---------------- | ----- | ----- | ------ | ---- | ------ |
| 状態値      |   1   |  39   |   77   |  84  |  122   |
| 幅            |  32   |  32   |   32   |  16  |   16   |
| `Number_of_Bits` |   5   |   5   |    5   |   4  |    4   |
| 割り当て順序 |   3   |   4   |    5   |   1  |    2   |
| `Baseline`       |  32   |  64   |   96   |   0  |   16   |
| 範囲            | 32-63 | 64-95 | 96-127 | 0-15 | 16-31  |

復号時には、現在の状態値を行番号に使い、必要な`Number_of_Bits`をビットストリームから読み取って、指定された`Baseline`を加算することで、次の状態値を決めます。

注:
単純な例として、確率が`1`のシンボルでは、`Baseline`は必ず`0`、`Number_of_Bits`は必ず`Accuracy_Log`になります。

この処理を既定の分布に適用した結果は[付録A][Appendix A]を参照してください。
