<h1 id="sds-internals-and-advanced-usage">SDSの内部構造と高度な使い方</h1>
<p>この文書の冒頭で、SDS文字列の確保方法を説明しましたが、利用者へ返すポインターの直前に格納する接頭部については、詳しく説明せず<em>ヘッダー</em>と呼びました。高度な使い方のために、SDSの内部を詳しく見て、その実装に使う構造体を示します。</p>
<pre><code class="language-c">struct sdshdr {&#10;    int len;&#10;    int free;&#10;    char buf[];&#10;};&#10;</code></pre>
<p>この構造体は、従来の文字列ライブラリーのものに似て見えるかもしれません。ただし、<code>buf</code>フィールドは異なります。ポインターではなく、長さを宣言していない配列なので、<code>buf</code>は実際には整数<code>free</code>の直後の最初のバイトを指します。そのため、SDS文字列の作成では、<code>sdshdr</code>構造体のサイズと文字列長の合計に、すべてのSDS文字列で必須のNUL終端用の1バイトを加えた大きさのメモリー領域を確保するだけです。</p>
<p>構造体の<code>len</code>フィールドは、その名のとおりSDS文字列の現在の長さで、SDS関数の呼び出しで文字列を変更するたびに計算されます。一方、<code>free</code>フィールドは、現在の確保領域のうち、さらに文字を格納するために使える空きメモリー量を表します。</p>
<p>したがって、実際のSDSの配置は次のようになります。</p>
<pre><code>+------------+------------------------+-----------+---------------\&#10;| Len | Free | H E L L O W O R L D \n | Null term |  Free space   \&#10;+------------+------------------------+-----------+---------------\&#10;             |&#10;             `-&gt; Pointer returned to the user.&#10;</code></pre>
<p>文字列の末尾に空き領域があるのは、無駄ではないかと思うかもしれません。実際、新しいSDS文字列を作成した直後には、末尾に空き領域はありません。ヘッダー、文字列、NUL終端だけを保持する、最小限のサイズを確保します。ただし、次のプログラムのような別のアクセス方法では、末尾に追加の空き領域が作られます。</p>
<pre><code class="language-c">s = sdsempty();&#10;s = sdscat(s,"foo");&#10;s = sdscat(s,"bar");&#10;s = sdscat(s,"123");&#10;</code></pre>
<p>SDSは効率を重視しているため、データを追加するたびに文字列を再確保することはできません。それでは非常に非効率になるため、文字列を大きくするたびに、<strong>空き領域をあらかじめ確保</strong>します。</p>
<p>先行確保のアルゴリズムは次のとおりです。より多くのバイトを保持するために文字列を再確保するたびに、実際には最低限必要なサイズの2倍を確保します。たとえば、現在の文字列が30バイトを保持していて、さらに2バイトを連結する場合、SDSは合計32バイトではなく64バイトを確保します。</p>
<p>ただし、先行して確保できる量には上限があり、<code>SDS_MAX_PREALLOC</code>で定義されています。SDSが追加で確保する領域は1MBを超えません。これは既定値で、変更できます。</p>
<h2 id="shrinking-strings">文字列の縮小</h2>
<pre><code class="language-c">sds sdsRemoveFreeSpace(sds s);&#10;size_t sdsAllocSize(sds s);&#10;</code></pre>
<p>プログラムの種類によっては、メモリー使用量を非常に小さくする必要があります。文字列の連結、トリミング、範囲の取得の後には、末尾にかなりの追加領域が残る場合があります。</p>
<p><code>sdsRemoveFreeSpace</code>関数を使うと、現在の内容を保持するのに必要な最小サイズまで文字列を縮められます。</p>
<pre><code class="language-c">s = sdsRemoveFreeSpace(s);&#10;</code></pre>
<p>指定した文字列の確保領域全体のサイズを取得する関数もあり、<code>sdsAllocSize</code>と呼ばれます。</p>
<pre><code class="language-c">sds s = sdsnew("Ladies and gentlemen");&#10;s = sdscat(s,"... welcome to the C language.");&#10;printf("%d\n", (int) sdsAllocSize(s));&#10;s = sdsRemoveFreeSpace(s);&#10;printf("%d\n", (int) sdsAllocSize(s));&#10;&#10;output&gt; 109&#10;output&gt; 59&#10;</code></pre>
<p>注：SDSの低水準APIは、危険を伴う操作をしていることへの注意として、キャメルケースを使っています。</p>
<h2 id="manual-modifications-of-sds-strings">SDS文字列の手動変更</h2>
<pre><code>void sdsupdatelen(sds s);&#10;</code></pre>
<p>SDS関数を使わず、SDS文字列を手動で変更したい場合があります。次の例では文字列の長さを暗黙に変更しますが、論理上の長さにも、NUL終端されたC文字列の長さを反映させたいものです。</p>
<p><code>sdsupdatelen</code>関数は、このための関数です。指定した文字列の内部の長さ情報を、<code>strlen</code>で取得した長さへ更新します。</p>
<pre><code class="language-c">sds s = sdsnew("foobar");&#10;s[2] = '\0';&#10;printf("%d\n", sdslen(s));&#10;sdsupdatelen(s);&#10;printf("%d\n", sdslen(s));&#10;&#10;output&gt; 6&#10;output&gt; 2&#10;</code></pre>
