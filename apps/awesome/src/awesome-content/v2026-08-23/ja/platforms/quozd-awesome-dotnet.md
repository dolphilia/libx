## Algorithms and Data structures

* [OneOf](https://github.com/mcintyre321/OneOf) - OneOfは、C#における分岐連合（discriminated unions）を提供し、コンパイル時における完全なマッチングを実現する.
* [Algorithmia](https://github.com/SolutionsDesign/Algorithmia) - .NET 3.5以降向けのアルゴリズムおよびデータ構造ライブラリ。Algorithmiaには、グラフ、優先度キュー、コマンド、アンダーオーバー（undo-redo）など、高度なアルゴリズムとデータ構造が含まれる.
* [Towel](https://github.com/ZacharyPatten/Towel) - データ構造、アルゴリズム、数学、メタデータ、拡張機能、コンソール、測定、その他便利な機能
* [Akade.IndexedSet](https://github.com/akade/Akade.IndexedSet) - 効率的なメモリ内インデックスとクエリをサポートする便利なデータ構造。範囲クエリや模糊な文字列マッチングを含む.

## API

* [FastEndpoints](https://github.com/FastEndpoints/FastEndpoints) - 古典的なASP.NET Core APIコントローラーとMinimal APIsの間の高パフォーマンスな中間層。REPR（[Request-Endpoint-Response](https://deviq.com/design-patterns/repr-design-pattern)）パターンを用いることで、コントローラーのテンプレートコードやモノリスックな構造を排除し、コードのコロケーションを改善する.
* [Telegram.Bot](https://github.com/TelegramBots/Telegram.Bot) - .NET用の[Telegram Bot API](https://core.telegram.org/bots/api)クライアント
* [WTelegramClient](https://github.com/wiz0u/WTelegramClient) - 最新バージョンの[Telegram Client API](https://core.telegram.org/methods)を用いて、Telegramのユーザーアカウントを自動化する.
* [ASP.NET Web API](https://dotnet.microsoft.com/apps/aspnet/apis) - ブラウザやモバイルデバイスなど、幅広いクライアントにアクセス可能なHTTPサービスを簡単に構築できるフレームワーク
* [Breeze](https://breeze.github.io/doc-net/) - OData 3プロトコルを用いて、豊かなデータアクセスを可能にするAPIフレームワーク。JavaScriptおよびC#向けのクライアントライブラリが提供される.
* [Mobius: C# API for Spark](https://github.com/Microsoft/Mobius) - MobiusはApache SparkにC#言語バインディングを追加し、Sparkドライバーのコードおよびデータ処理操作をC#で実装可能にする.
* [ServiceStack](https://github.com/ServiceStack/ServiceStack) - すべての用途に適した、丁寧に設計された、驚異的に速く、非常に楽しいウェブサービス
* [Ocelot](https://github.com/ThreeMammals/Ocelot) - .NET Core API ガートウェイ
* [CommandQuery](https://github.com/hlaueriksson/CommandQuery) - コマンドとクエリの分離（CQS）を、🌐ASP.NET Core ⚡AWS Lambda ⚡Azure Functions ⚡Google Cloud Functions 🌐ASP.NET Web API 2 に適用する
* [Population.NET](https://github.com/Authentic199/Population.NET) - .NETライブラリにより、クライアントが必要な正確なフィールドを指定できるため、すべてのフィールドを取得するデフォルト動作を回避し、不要なデータ転送を削減する.
* [Wissance.WebApiTookit](https://github.com/Wissance/WebApiToolkit) - REST APIおよびgRPCサービスの構築を簡素化するライブラリとクラスのセット。1行のコードで完全なRESTコントローラーを実現し、書くコード量を大幅に削減する.

* [Plastic](https://github.com/sang-hyeon/Plastic) - Plasticは、ドメイン、アプリケーションルール、ビジネスルールまたはビジネスロジックをアプリケーション内で封じ込めるように設計されており、これにはコマンドパターンが使用されています。
* [Signals](https://github.com/EmitKnowledge/Signals) - Signalsは.NET5に基づいたフレームワークで、開発チームの品質と生産性を高めるために、ツール、アスペクト、プロセスを提供しています。
* [Spring.Net](https://github.com/spring-projects/spring-net) - Spring.NETは、エンタープライズ.NETアプリケーションの開発を容易にするオープンソースアプリケーションフレームワーク
* [DotNetty](https://github.com/Azure/DotNetty) - DotNettyは、Nettyのポートであり、アシンクネスイベント駆動ネットワークアプリケーションフレームワークで、維持性の高い高性能プロトコルサーバーおよびクライアントの迅速開発を可能にします。
* [AspectCore Framework](https://github.com/dotnetcore/AspectCore-Framework) - AspectCore Frameworkは、.NET Coreおよび.NET Framework向けのアスペクト指向プログラミングベースのプラットフォームフレームワークであり、アスペクトインターセプタ、依存性注入、Webアプリケーション、データ検証などにサポートされています。
* [ActualLab.Fusion](https://github.com/ActualLab/Fusion) - Skip SignalRおよびgRPC。リアルタイムBlazorおよびMAUIアプリケーションを構築する際に、通常のリアルタイム更新コードの0.1％しか書かず、実際のAPIリクエストを10倍、あるいはFusionの透過的かつ完全に整合したキャッシュにより1000倍も処理できます。[Samples](https://github.com/ActualLab/Fusion.Samples)。[Documentation](https://fusion.actuallab.net/)。
* [silky](https://github.com/liuhll/silky) - Silkyフレームワークは、.NETプラットフォームでシンプルなコードと設定を使って、開発者が迅速にマイクロサービス開発フレームワークを構築できるように設計されています。
* [Positron-JS](https://github.com/Positron-JS/positron-web-view) - ハイブリッドアプリケーションから.NET APIにアクセスできるネイティブJavaScriptコンテキストを備えた高度なWeb View（PositronWebView）を提供。capacitor/cordovaにインスパイアされたもの。
