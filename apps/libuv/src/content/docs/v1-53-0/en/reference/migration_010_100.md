<article class="libuv-document" id="furo-main-content" role="main">&#10;<section id="libuv-0-10-1-0-0-migration-guide">&#10;<span id="migration-010-100"></span><h1>libuv 0.10 -&gt; 1.0.0 migration guide<a class="headerlink" href="#libuv-0-10-1-0-0-migration-guide" title="Permalink to this heading">¶</a></h1>&#10;<p>Some APIs changed quite a bit throughout the 1.0.0 development process. Here&#10;is a migration guide for the most significant changes that happened after 0.10&#10;was released.</p>&#10;<section id="loop-initialization-and-closing">&#10;<h2>Loop initialization and closing<a class="headerlink" href="#loop-initialization-and-closing" title="Permalink to this heading">¶</a></h2>&#10;<p>In libuv 0.10 (and previous versions), loops were created with <cite>uv_loop_new</cite>, which&#10;allocated memory for a new loop and initialized it; and destroyed with <cite>uv_loop_delete</cite>,&#10;which destroyed the loop and freed the memory. Starting with 1.0, those are deprecated&#10;and the user is responsible for allocating the memory and then initializing the loop.</p>&#10;<p>libuv 0.10</p>&#10;<div class="highlight-default notranslate"><div class="highlight"><pre><span></span><span class="n">uv_loop_t</span><span class="o">*</span> <span class="n">loop</span> <span class="o">=</span> <span class="n">uv_loop_new</span><span class="p">();</span>&#10;<span class="o">...</span>&#10;<span class="n">uv_loop_delete</span><span class="p">(</span><span class="n">loop</span><span class="p">);</span>&#10;</pre></div>&#10;</div>&#10;<p>libuv 1.0</p>&#10;<div class="highlight-default notranslate"><div class="highlight"><pre><span></span><span class="n">uv_loop_t</span><span class="o">*</span> <span class="n">loop</span> <span class="o">=</span> <span class="n">malloc</span><span class="p">(</span><span class="n">sizeof</span> <span class="o">*</span><span class="n">loop</span><span class="p">);</span>&#10;<span class="n">uv_loop_init</span><span class="p">(</span><span class="n">loop</span><span class="p">);</span>&#10;<span class="o">...</span>&#10;<span class="n">uv_loop_close</span><span class="p">(</span><span class="n">loop</span><span class="p">);</span>&#10;<span class="n">free</span><span class="p">(</span><span class="n">loop</span><span class="p">);</span>&#10;</pre></div>&#10;</div>&#10;<div class="admonition note">&#10;<p class="admonition-title">Note</p>&#10;<p>Error handling was omitted for brevity. Check the documentation for <a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/loop/#c.uv_loop_init" title="uv_loop_init"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_loop_init()</span></code></a>&#10;and <a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/loop/#c.uv_loop_close" title="uv_loop_close"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_loop_close()</span></code></a>.</p>&#10;</div>&#10;</section>&#10;<section id="error-handling">&#10;<h2>Error handling<a class="headerlink" href="#error-handling" title="Permalink to this heading">¶</a></h2>&#10;<p>Error handling had a major overhaul in libuv 1.0.  <span class="n">uv_err_t</span> <span class="n">err</span> <span class="o">=</span> <span class="n">uv_last_error</span><span class="p">(</span><span class="n">uv_default_loop</span><span class="p">());</span>&#10;  <span class="o">/*</span> <span class="n">err</span><span class="o">.</span><span class="n">code</span> <span class="n">contains</span> <span class="n">UV_EADDRINUSE</span> <span class="o">*/</span>&#10;<span class="p">}</span>&#10;</pre></div>&#10;</div>&#10;<p>libuv 1.0</p>&#10;<div class="highlight-default notranslate"><div class="highlight"><pre><span></span><span class="o">...</span> <span class="n">assume</span> <span class="s1">'server'</span> <span class="ow">is</span> <span class="n">a</span> <span class="n">TCP</span> <span class="n">server</span> <span class="n">which</span> <span class="ow">is</span> <span class="n">already</span> <span class="n">listening</span>&#10;<span class="n">r</span> <span class="o">=</span> <span class="n">uv_listen</span><span class="p">((</span><span class="n">uv_stream_t</span><span class="o">*</span><span class="p">)</span> <span class="n">server</span><span class="p">,</span> <span class="mi">511</span><span class="p">,</span> <span class="n">NULL</span><span class="p">);</span>&#10;<span class="k">if</span> <span class="p">(</span><span class="n">r</span> <span class="o">&lt;</span> <span class="mi">0</span><span class="p">)</span> <span class="p">{</span>&#10;  <span class="o">/*</span> <span class="n">r</span> <span class="n">contains</span> <span class="n">UV_EADDRINUSE</span> <span class="o">*/</span>&#10;<span class="p">}</span>&#10;</pre></div>&#10;</div>&#10;</section>&#10;<section id="threadpool-changes">&#10;<h2>Threadpool changes<a class="headerlink" href="#threadpool-changes" title="Permalink to this heading">¶</a></h2>&#10;<p>In libuv 0.10 Unix used a threadpool which defaulted to 4 threads, while Windows used the&#10;<cite>QueueUserWorkItem</cite> API, which uses a Windows internal threadpool, which defaults to 512&#10;threads per process.</p>&#10;<p>In 1.0, we unified both implementations, so Windows now uses the same implementation Unix&#10;does.    <span class="n">buf</span><span class="o">-&gt;</span><span class="n">base</span> <span class="o">=</span> <span class="n">malloc</span><span class="p">(</span><span class="n">size</span><span class="p">);</span>&#10;    <span class="n">buf</span><span class="o">-&gt;</span><span class="nb">len</span> <span class="o">=</span> <span class="n">size</span><span class="p">;</span>&#10;<span class="p">}</span>&#10;</pre></div>&#10;</div>&#10;</section>&#10;<section id="unification-of-ipv4-ipv6-apis">&#10;<h2>Unification of IPv4 / IPv6 APIs<a class="headerlink" href="#unification-of-ipv4-ipv6-apis" title="Permalink to this heading">¶</a></h2>&#10;<p>libuv 1.0 unified the IPv4 and IPv6 APIS. In 1.0, this function got renamed to <a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/fs/#c.uv_fs_scandir" title="uv_fs_scandir"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_fs_scandir()</span></code></a>, since it’s&#10;actually implemented using <code class="docutils literal notranslate"><span class="pre">scandir(3)</span></code>.</p>&#10;<p>In addition, instead of allocating a full list strings, the user is able to get one&#10;result at a time by using the <a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/fs/#c.uv_fs_scandir_next" title="uv_fs_scandir_next"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_fs_scandir_next()</span></code></a> function.
