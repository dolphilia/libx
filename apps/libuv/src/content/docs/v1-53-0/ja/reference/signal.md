<article class="libuv-document" id="furo-main-content" role="main">&#10;<section id="uv-signal-t-signal-handle">&#10;<span id="signal"></span><h1><a class="reference internal" href="#c.uv&#95;signal&#95;t" title="uv&#95;signal&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;signal&#95;t</span></code></a> — シグナルハンドル<a class="headerlink" href="#uv-signal-t-signal-handle" title="この見出しへの固定リンク">¶</a></h1>&#10;<p>シグナルハンドルは、イベントループごとにUnix形式のシグナル処理を実装します。</p>&#10;<section id="windows-notes">&#10;<h2>Windowsに関する注記<a class="headerlink" href="#windows-notes" title="この見出しへの固定リンク">¶</a></h2>&#10;<p>一部のシグナルの受信をエミュレートします。</p>&#10;<ul class="simple">&#10;<li><p>SIGINTは、通常、ユーザーがCTRL+Cを押したときに届きます。ただし、Unixと同様に、端末のrawモードが有効な場合は発生しません。</p></li>&#10;<li><p>SIGBREAKは、ユーザーがCTRL+BREAKを押したときに届きます。</p></li>&#10;<li><p>SIGHUPは、ユーザーがコンソールウィンドウを閉じたときに発生します。SIGHUPを受けたプログラムには、後処理のために約10秒が与えられます。その後、Windowsは無条件にプログラムを終了します。</p></li>&#10;<li><p>SIGWINCHは、libuvがコンソールのサイズ変更を検出するたびに発生します。libuvアプリがコンソールエミュレーターで動作している場合や、32ビットのlibuvアプリが64ビットシステムで動作している場合は、SIGWINCHをエミュレートします。この場合、SIGWINCHが常に適時に届くとは限りません。書き込み可能な<a class="reference internal" href="/docs/libuv/v1-53-0/ja/reference/tty/#c.uv&#95;tty&#95;t" title="uv&#95;tty&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;tty&#95;t</span></code></a>ハンドルでは、カーソルが移動したときだけサイズの変更を検出します。読み取り可能な<a class="reference internal" href="/docs/libuv/v1-53-0/ja/reference/tty/#c.uv&#95;tty&#95;t" title="uv&#95;tty&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;tty&#95;t</span></code></a>ハンドルを使う場合は、ハンドルがrawモードであり、読み取り中の場合にだけ、コンソールバッファーのサイズ変更を検出します。</p></li>&#10;<li><p>他のシグナルの監視ハンドルも作成できますが、これらのシグナルを受信することはありません。該当するシグナルは次のとおりです: <cite>SIGILL</cite>、<cite>SIGABRT</cite>、<cite>SIGFPE</cite>、<cite>SIGSEGV</cite>、<cite>SIGTERM</cite>、<cite>SIGKILL.</cite></p></li>&#10;<li><p>raise()やabort()でプログラムからシグナルを発生させても、libuvは検出しません。そのため、シグナルの監視ハンドルは反応しません。</p></li>&#10;</ul>&#10;<div class="versionchanged">&#10;<p><span class="versionmodified changed">バージョン1.15.0での変更: </span>WindowsのSIGWINCHサポートを改善しました。</p>&#10;</div>&#10;<div class="versionchanged">&#10;<p><span class="versionmodified changed">バージョン1.31.0での変更: </span>64ビットWindows上の32ビットlibuvのSIGWINCHサポートを、以前の実装へ戻しました。</p>&#10;</div>&#10;</section>&#10;<section id="unix-notes">&#10;<h2>Unixに関する注記<a class="headerlink" href="#unix-notes" title="この見出しへの固定リンク">¶</a></h2>&#10;<ul class="simple">&#10;<li><p>SIGKILLとSIGSTOPは捕捉できません。</p></li>&#10;<li><p>SIGBUS、SIGFPE、SIGILL、SIGSEGVをlibuvで処理すると、未定義動作になります。</p></li>&#10;<li><p>SIGABRTを<cite>abort()</cite>が生成した場合、たとえば<cite>assert()</cite>経由の場合には、libuvで捕捉しません。</p></li>&#10;<li><p>Linuxでは、SIGRT0とSIGRT1（シグナル番号32と33）を、NPTLのpthreadsライブラリーがスレッド管理に使います。これらのシグナルの監視ハンドルを設定すると、予測不能な動作が生じるため、強く非推奨とします。将来のlibuvでは、これらを単に拒否する可能性があります。</p></li>&#10;</ul>&#10;</section>&#10;<section
