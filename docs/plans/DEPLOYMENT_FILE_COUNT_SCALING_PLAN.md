# デプロイ成果物ファイル数の拡張計画

- 作成日: 2026-08-11
- 入力資料: `docs/notes/DEPLOYMENT_FILE_COUNT_SCALING_RESEARCH.md`
- 根拠原則: `docs/spec/PROJECT_PRINCIPLES.md`
- ステータス: 今回範囲の実施完了

## 1. 目的

Cloudflareの上限へ達する前に、成果物の増加を検出し、不要ファイルを抑制し、サイト単位の分割へ安全に移行できる状態を作る。

## 2. 今回実施する範囲

1. Wranglerを100,000静的アセット対応のv4.34.0以上へ更新する。
2. 統合`dist/`のファイル数、容量、最大ファイル、拡張子別件数を検査する。
3. 暫定20,000件を基準に60%で警告、90%でデプロイを停止する。
4. 25MiBを超える単一ファイルを停止対象にする。
5. デプロイコマンドとGitHub Actionsの双方で検査を必須にする。
6. 参照されないサイドバーgzip版を廃止する。
7. `pages/public/sidebar`への二重コピーを廃止する。
8. 回帰テストと全体ビルドで成果物を検証する。

Pagesダッシュボードへの環境変数設定、上限確認用の実デプロイ、Workers／R2リソース作成は外部状態を変更するため、今回のリポジトリ内実装には含めない。

## 3. 受け入れ条件

- `pnpm check:deployment-assets`で現在の成果物件数と予算が表示される。
- ファイル数が既定20,000件の90%に達すると終了コード1になる。
- 25MiBを超えるファイルがあると終了コード1になる。
- 通常のデプロイ経路が検査を迂回しない。
- サイドバーは`.json`だけを生成し、`.json.gz`を生成しない。
- 統合出力に`pages/public/sidebar`が存在しない。
- 文書ページが従来どおり`/sidebar/sidebar-*.json`を参照する。
- `pnpm test:runtime`、`pnpm build`、`pnpm test:smoke`が成功する。

## 4. 閾値運用

実効上限を`L`として次を使用する。

| 水準 | 閾値 | 対応 |
| --- | ---: | --- |
| 通常 | 60%未満 | Pages継続、傾向記録 |
| 警告 | 60%以上 | 増加要因を分析し、分割方式を決定 |
| 移行準備 | 80%以上 | Workers Static Assetsのサイト分割を本番相当で検証 |
| 停止 | 90%以上 | CIで停止し、分割または削減を完了するまで配信しない |

Pages Direct Uploadの100,000件適用を確認できるまでは`L=20,000`とする。確認後はCIの`DEPLOYMENT_FILE_LIMIT=100000`へ変更する。

## 5. 後続フェーズ

### フェーズ2: 上限適用確認

- Pages設定へ`PAGES_WRANGLER_MAJOR_VERSION=4`を追加する。
- 20,000件を超える生成fixtureをpreviewへデプロイする。
- 適用できない場合はCloudflareサポートへ確認する。

### フェーズ3: サイト単位分割の実証

- 1サイトをWorkers Static Assetsへ複製する。
- サブドメイン方式と既存`/docs/{site}`維持方式を比較する。
- 表示性能、404、ヘッダー、ロールバック、選択的デプロイを検証する。

### フェーズ4: 100,000件超への対応

- 単一サイトを版または内容上の境界で分割できるか先に判断する。
- 分割不能ならR2に不変なリリース接頭辞で配置し、Workerが公開リリースを切り替える構成を試作する。
- CDNキャッシュヒット率とR2 Class B操作費を測定する。

## 6. 完了記録

2026-08-11に今回範囲を完了した。

- Wranglerを3.114.11から、Node 20をサポートする4.60.0へ厳密固定した。
- `scripts/check-deployment-assets.js`を追加し、既定20,000件、警告12,000件、停止18,000件、個別25MiBの検査を実装した。
- ローカルの`pnpm deploy`とGitHub Actionsのデプロイ前に検査を追加した。
- サイドバーgzip生成と`pages/public/sidebar`への二重コピーを廃止した。
- 統合成果物は469件から436件へ33件（約7.0%）減少した。
- 統合成果物の容量は約13MiBから11.54MiBへ減少した。
- `.json.gz`と`pages/public/sidebar`はいずれも統合成果物中0件になった。
- `pnpm check:deployment-assets`、統合ビルド、`pnpm check`が成功した。

残る外部作業は、Pagesプロジェクト設定への`PAGES_WRANGLER_MAJOR_VERSION=4`追加と、Direct Uploadで100,000件枠が適用されることの確認である。確認までは20,000件を実効上限として維持する。
