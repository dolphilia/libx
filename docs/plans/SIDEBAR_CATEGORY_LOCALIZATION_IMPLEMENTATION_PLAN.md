# サイドバーカテゴリ多言語化 実装計画

## 目的

各ドキュメントサイトの左サイドバーにあるグループ見出しを、ページの表示言語に合わせて安定して表示する。カテゴリの並び順、識別子、表示名を分離し、サイト追加時にも同じ規則を適用できるようにする。

## 正式な契約

- `01-overview`のようなディレクトリ名では、`01-`を並び順、`overview`をカテゴリIDとして扱う。
- カテゴリ表示名は各サイトの単一設定ファイル`src/config/project.config.jsonc`に置く。
- 表示名は「表示言語 → プロジェクトの既定言語 → IDの人間向け整形」の順で解決する。
- カテゴリ構造はディレクトリから決定し、文書Frontmatterでは上書きしない。
- 既定言語の表示名欠落と、番号付きカテゴリIDは自動検査でエラーにする。既定言語以外の欠落はフォールバックを許容する。

## 実装工程

1. カテゴリID正規化・表示名解決を`packages/content-utils`へ集約する。
2. 通常生成、選択的生成、Astro実行時生成の3経路を共通ロジックへ移行する。
3. GLFWとLuaの設定キーを番号なしIDへ移行し、不要なFrontmatterの`category`を廃止する。
4. 設定スキーマとリポジトリ整合性検査で契約違反を検出する。
5. 単体テストと生成済みサイドバーの回帰テストを追加し、複数サイトのビルドで確認する。
6. テンプレートと文書追加ガイドへ運用規則を反映する。

## 完了条件

- GLFWとLuaの日本語ページで、すべてのグループ見出しが設定どおり日本語になる。
- 英語を既定言語と仮定せず、サイト設定の`language.default`が使われる。
- 通常・選択的・実行時の各生成経路が同じカテゴリIDとフォールバック規則を使う。
- 番号付き翻訳キーと既定言語の欠落を検査で発見できる。
- 関連テスト、型検査、対象サイトのビルドが成功する。
