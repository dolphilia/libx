### 4.2 証拠の配置

複数版の状態を一つのJSONへ上書きしないため、Awesomeの版別証拠を次へ分離する。

```text
docs/notes/document-import/awesome/
├── README.md
├── OPERATIONS.md
├── snapshots/
│   ├── v2026-08-20/
│   │   ├── SOURCE_MANIFEST.md
│   │   ├── SOURCES.lock.json
│   │   ├── CONTENT_MAP.json
│   │   ├── EXCLUSIONS.json
│   │   ├── BATCH_STATUS.json
│   │   ├── MACHINE_AUDIT.json
│   │   ├── FINAL_REVIEW_QUEUE.json
│   │   └── FINAL_REVIEW_RESULTS.json
│   └── v2026-08-23/
│       └── 同じ版別成果物
└── migration/
    ├── SNAPSHOT_ARTIFACT_MIGRATION.json
    └── RECONCILIATION_REPORT.json
```

既存スクリプトへ`--snapshot=<id>`と版別記録ディレクトリを追加する。引数省略時に暗黙で最新版を選ばず、書込みコマンドでは対象版を必須にする。既存の直下ファイルを移動する前に、旧パスから新パスへの対応、ハッシュ、利用スクリプト、互換期間を`SNAPSHOT_ARTIFACT_MIGRATION.json`へ記録する。

### 4.3 定本の不変条件

- 英語定本は固定入力、除外記録、正規化規則からだけ生成する。
- `apps/awesome/src/awesome-content/<version>/en/`を直接編集して差分を確定しない。
- 広告、バナー、支援案内などを削除する場合は`EXCLUSIONS.json`へ固定コミット、位置、断片ハッシュ、理由を記録する。
- 表示上のCSS、外部リンクアイコン、レイアウト変更は本文ハッシュと分離する。
- 共通変換規則を変更した場合は、両版を再生成し、意図しない本文差分が0件であることを確認する。
