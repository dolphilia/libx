<div class="contents rapidjson-document">&#10;<div class="textblock"><p><a class="anchor" id="autotoc_md71"></a></p>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md72"></a>&#10;General</h1>&#10;<ol type="1">&#10;<li><p class="startli">What is RapidJSON?</p>&#10;<p class="startli">RapidJSON is a C++ library for parsing and generating JSON. You may check all <a class="el" href="/docs/rapidjson-static-trial/v1-1-0/en/01-docs/132-md_doc_2features/" title="Features">features</a> of it.</p>&#10;</li>&#10;<li><p class="startli">Why is RapidJSON named so?</p>&#10;<p class="startli">It is inspired by <a href="http://rapidxml.sourceforge.net/">RapidXML</a>, which is a fast XML DOM parser.</p>&#10;</li>&#10;<li><p class="startli">Is RapidJSON similar to RapidXML?</p>&#10;<p class="startli">RapidJSON borrowed some designs of RapidXML, including <em>in situ</em> parsing, header-only library. But the two APIs are completely different. Also RapidJSON provide many features that are not in RapidXML.</p>&#10;</li>&#10;<li><p class="startli">Is RapidJSON free?</p>&#10;<p class="startli">Yes, it is free under MIT license. It can be used in commercial applications. Please check the details in <a href="https://github.com/miloyip/rapidjson/blob/master/license.txt">license.txt</a>.</p>&#10;</li>&#10;<li><p class="startli">Is RapidJSON small? What are its dependencies?</p>&#10;<p class="startli">Yes. A simple executable which parses a JSON and prints its statistics is less than 30KB on Windows.</p>&#10;<p class="startli">RapidJSON depends on C++ standard library only.</p>&#10;</li>&#10;<li><p class="startli">How to install RapidJSON?</p>&#10;<p class="startli">Check <a href="https://miloyip.github.io/rapidjson/">Installation section</a>.</p>&#10;</li>&#10;<li><p class="startli">Can RapidJSON run on my platform?</p>&#10;<p class="startli">RapidJSON has been tested in many combinations of operating systems, compilers and CPU architecture by the community. But we cannot ensure that it can be run on your particular platform. Building and running the unit test suite will give you the answer.</p>&#10;</li>&#10;<li><p class="startli">Does RapidJSON support C++03? C++11?</p>&#10;<p class="startli">RapidJSON was firstly implemented for C++03. Later it added optional support of some C++11 features (e.g., move constructor, <span class="tt">noexcept</span>). RapidJSON shall be compatible with C++03 or C++11 compliant compilers.</p>&#10;</li>&#10;<li><p class="startli">Does RapidJSON really work in real applications?</p>&#10;<p class="startli">Yes. It is deployed in both client and server real applications. A community member reported that RapidJSON in their system parses 50 million JSONs daily.</p>&#10;</li>&#10;<li><p class="startli">How RapidJSON is tested?</p>&#10;<p class="startli">RapidJSON contains a unit test suite for automatic testing. <a href="https://travis-ci.org/miloyip/rapidjson/">Travis</a>(for Linux) and <a href="https://ci.appveyor.com/project/miloyip/rapidjson/">AppVeyor</a>(for Windows) will compile and run the unit test suite for all modifications. The test process also uses Valgrind (in Linux) to detect memory leaks.</p>&#10;</li>&#10;<li><p class="startli">Is RapidJSON well documented?</p>&#10;<p class="startli">RapidJSON provides user guide and API documentationn.</p>&#10;</li>&#10;<li><p class="startli">Are there alternatives?</p>&#10;<p class="startli">Yes, there are a lot alternatives. For example, <a href="https://github.com/miloyip/nativejson-benchmark">nativejson-benchmark</a> has a listing of open-source C/C++ JSON libraries. <a href="http://www.json.org/">json.org</a> also has a list.</p>&#10;</li>&#10;</ol>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md73"></a>&#10;JSON</h1>&#10;<ol type="1">&#10;<li><p class="startli">What is JSON?</p>&#10;<p class="startli">JSON (JavaScript Object Notation) is a lightweight data-interchange format. It uses human readable text format. More details of JSON can be referred to <a href="http://www.ietf.org/rfc/rfc7159.txt">RFC7159</a> and <a href="http://www.ecma-international.org/publications/standards/Ecma-404.htm">ECMA-404</a>.</p>&#10;</li>&#10;<li><p class="startli">What are applications of JSON?</p>&#10;<p class="startli">JSON are commonly used in web applications for transferring structured data. It is also used as a file format for data persistence.</p>&#10;</li>&#10;</ol>&#10;<ol type="1">&#10;<li><p class="startli">Does RapidJSON conform to the JSON standard?</p>&#10;<p class="startli">Yes. RapidJSON is fully compliance with <a href="http://www.ietf.org/rfc/rfc7159.txt">RFC7159</a> and <a href="http://www.ecma-international.org/publications/standards/Ecma-404.htm">ECMA-404</a>. It can handle corner cases, such as supporting null character and surrogate pairs in JSON strings.</p>&#10;</li>&#10;<li><p class="startli">Does RapidJSON support relaxed syntax?</p>&#10;<p class="startli">Currently no. RapidJSON only support the strict standardized format. Support on related syntax is under discussion in this <a href="https://github.com/miloyip/rapidjson/issues/36">issue</a>.</p>&#10;</li>&#10;</ol>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md74"></a>&#10;DOM and SAX</h1>&#10;<ol type="1">&#10;<li><p class="startli">What is DOM style API?</p>&#10;<p class="startli">Document Object Model (DOM) is an in-memory representation of JSON for query and manipulation.</p>&#10;</li>&#10;<li><p class="startli">What is SAX style API?</p>&#10;<p class="startli">SAX is an event-driven API for parsing and generation.</p>&#10;</li>&#10;<li><p class="startli">Should I choose DOM or SAX?</p>&#10;<p class="startli">DOM is easy for query and manipulation. SAX is very fast and memory-saving but often more difficult to be applied.</p>&#10;</li>&#10;<li><p class="startli">What is <em>in situ</em> parsing?</p>&#10;<p class="startli"><em>in situ</em> parsing decodes the JSON strings directly into the input JSON. This is an optimization which can reduce memory consumption and improve performance, but the input JSON will be modified. Check <a class="el" href="/docs/rapidjson-static-trial/v1-1-0/en/01-docs/129-md_doc_2dom/" title="DOM">in-situ parsing</a> for details.</p>&#10;</li>&#10;<li><p class="startli">When does parsing generate an error?</p>&#10;<p class="startli">The parser generates an error when the input JSON contains invalid syntax, or a value can not be represented (a number is too big), or the handler of parsers terminate the parsing. Check <a class="el" href="/docs/rapidjson-static-trial/v1-1-0/en/01-docs/129-md_doc_2dom/" title="DOM">parse error</a> for details.</p>&#10;</li>&#10;<li><p class="startli">What error information is provided?</p>&#10;<p class="startli">The error is stored in <span class="tt">ParseResult</span>, which includes the error code and offset (number of characters from the beginning of JSON). The error code can be translated into human-readable error message.</p>&#10;</li>&#10;<li><p class="startli">Why not just using <span class="tt">double</span> to represent JSON number?</p>&#10;<p class="startli">Some applications use 64-bit unsigned/signed integers. And these integers cannot be converted into <span class="tt">double</span> without loss of precision. class="startli">What is move semantics? Why?</p>&#10;<p class="startli">Instead of copy semantics, move semantics is used in <span class="tt">Value</span>. That means, when assigning a source value to a target value, the ownership of source value is moved to the target value.</p>&#10;<p class="startli">Since moving is faster than copying, this design decision forces user to aware of the copying overhead.</p>&#10;</li>&#10;<li><p class="startli">How to copy a value?</p>&#10;<p class="startli">There are two APIs: constructor with allocator, and <span class="tt">CopyFrom()</span>. See <a class="el" href="/docs/rapidjson-static-trial/v1-1-0/en/01-docs/139-md_doc_2tutorial/" title="Tutorial">Deep Copy Value</a> for an example.</p>&#10;</li>&#10;<li><p class="startli">Why do I need to provide the length of string?</p>&#10;<p class="startli">Since C string is null-terminated, the length of string needs to be computed via <span class="tt">strlen()</span>, with linear runtime complexity. This incurs an unncessary overhead of many operations, if the user already knows the length of string.</p>&#10;<p class="startli">Also, RapidJSON can handle <span class="tt">\u0000</span> (null character) within a string. If a string contains null characters, <span class="tt">strlen()</span> cannot return the true length of it. In such case user must provide the length of string explicitly.</p>&#10;</li>&#10;<li><p class="startli">Why do I need to provide allocator parameter in many DOM manipulation API?</p>&#10;<p class="startli">Since the APIs are member functions of <span class="tt">Value</span>, we do not want to save an allocator pointer in every <span class="tt">Value</span>.</p>&#10;</li>&#10;<li><p class="startli">Does it convert between numerical types?</p>&#10;<p class="startli">When using <span class="tt">GetInt()</span>, <span class="tt">GetUint()</span>, ... conversion may occur. For integer-to-integer conversion, it only convert when it is safe (otherwise it will assert). However, when converting a 64-bit signed/unsigned integer to double, it will convert but be aware that it may lose precision. A number with fraction, or an integer larger than 64-bit, can only be obtained by <span class="tt">GetDouble()</span>.</p>&#10;</li>&#10;</ol>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md76"></a>&#10;Reader/Writer (SAX)</h1>&#10;<ol type="1">&#10;<li><p class="startli">Why don't we just <span class="tt">printf</span> a JSON? Why do we need a <span class="tt">Writer</span>?</p>&#10;<p class="startli">Most importantly, <span class="tt">Writer</span> will ensure the output JSON is well-formed. Calling SAX events incorrectly (e.g. <span class="tt">StartObject()</span> pairing with <span class="tt">EndArray()</span>) will assert. Besides, <span class="tt">Writer</span> will escapes strings (e.g., <span class="tt">\n</span>). Finally, the numeric output of <span class="tt">printf()</span> may not be a valid JSON number, especially in some locale with digit delimiters. And the number-to-string conversion in <span class="tt">Writer</span> is implemented with very fast algorithms, which outperforms than <span class="tt">printf()</span> or <span class="tt">iostream</span>.</p>&#10;</li>&#10;<li><p class="startli">Can I pause the parsing process and resume it later?</p>&#10;<p class="startli">This is not directly supported in the current version due to performance consideration. However, if the execution environment supports multi-threading, user can parse a JSON in a separate thread, and pause it by blocking in the input stream.</p>&#10;</li>&#10;</ol>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md77"></a>&#10;Unicode</h1>&#10;<ol type="1">&#10;<li><p class="startli">Does it support UTF-8, UTF-16 and other format?</p>&#10;<p class="startli">Yes. It fully support UTF-8, UTF-16 (LE/BE), UTF-32 (LE/BE) and ASCII.</p>&#10;</li>&#10;<li><p class="startli">Can it validate the encoding?</p>&#10;<p class="startli">Yes, just pass <span class="tt">kParseValidateEncodingFlag</span> to <span class="tt">Parse()</span>. If there is invalid encoding in the stream, it wil generate <span class="tt">kParseErrorStringInvalidEncoding</span> error.</p>&#10;</li>&#10;<li><p class="startli">What is surrogate pair? Does RapidJSON support it?</p>&#10;<p class="startli">JSON uses UTF-16 encoding when escaping unicode character, e.g. <span class="tt">\u5927</span> representing Chinese character "big". To handle characters other than those in basic multilingual plane (BMP), UTF-16 encodes those characters with two 16-bit values, which is called UTF-16 surrogate pair. For example, the Emoji character U+1F602 can be encoded as <span class="tt">\uD83D\uDE02</span> in JSON.</p>&#10;<p class="startli">RapidJSON fully support parsing/generating UTF-16 surrogates.</p>&#10;</li>&#10;<li><p class="startli">Can it handle <span class="tt">\u0000</span> (null character) in JSON string?</p>&#10;<p class="startli">Yes. RapidJSON fully support null character in JSON string. However, user need to be aware of it and using <span class="tt">GetStringLength()</span> and related APIs to obtain the true length of string.</p>&#10;</li>&#10;<li><p class="startli">Can I output <span class="tt">\uxxxx</span> for all non-ASCII character?</p>&#10;<p class="startli">Yes, use <span class="tt">ASCII&lt;&gt;</span> as output encoding template parameter in <span class="tt">Writer</span> can enforce escaping those characters.</p>&#10;</li>&#10;</ol>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md78"></a>&#10;Stream</h1>&#10;<ol type="1">&#10;<li><p class="startli">I have a big JSON file. Should I load the whole file to memory?</p>&#10;<p class="startli">User can use <span class="tt">FileReadStream</span> to read the file chunk-by-chunk. But for <em>in situ</em> parsing, the whole file must be loaded.</p>&#10;</li>&#10;<li><p class="startli">Can I parse JSON while it is streamed from network?</p>&#10;<p class="startli">Yes. User can implement a custom stream for this. Please refer to the implementation of <span class="tt">FileReadStream</span>.</p>&#10;</li>&#10;<li><p class="startli">I don't know what encoding will the JSON be. How to handle them?</p>&#10;<p class="startli">You may use <span class="tt">AutoUTFInputStream</span> which detects the encoding of input stream automatically. However, it will incur some performance overhead.</p>&#10;</li>&#10;<li><p class="startli">What is BOM? How RapidJSON handle it?</p>&#10;<p class="startli"><a href="http://en.wikipedia.org/wiki/Byte_order_mark">Byte order mark (BOM)</a> sometimes reside at the beginning of file/stream to indiciate the UTF encoding type of it.</p>&#10;<p class="startli">RapidJSON's <span class="tt">EncodedInputStream</span> can detect/consume BOM. <span class="tt">EncodedOutputStream</span> can optionally write a BOM. See <a class="el" href="/docs/rapidjson-static-trial/v1-1-0/en/01-docs/138-md_doc_2stream/" title="Stream">Encoded Streams</a> for example.</p>&#10;</li>&#10;<li><p class="startli">Why little/big endian is related?</p>&#10;<p class="startli">little/big endian of stream is an issue for UTF-16 and UTF-32 streams, but not UTF-8 stream.</p>&#10;</li>&#10;</ol>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md79"></a>&#10;Performance</h1>&#10;<ol type="1">&#10;<li><p class="startli">Is RapidJSON really fast?</p>&#10;<p class="startli">Yes. It may be the fastest open source JSON library. There is a <a href="https://github.com/miloyip/nativejson-benchmark">benchmark</a> for evaluating performance of C/C++ JSON libaries.</p>&#10;</li>&#10;<li><p class="startli">Why is it fast?</p>&#10;<p class="startli">Many design decisions of RapidJSON is aimed at time/space performance. These may reduce user-friendliness of APIs. Besides, it also employs low-level optimizations (intrinsics, SIMD) and special algorithms (custom double-to-string, string-to-double conversions).</p>&#10;</li>&#10;<li><p class="startli">What is SIMD? How it is applied in RapidJSON?</p>&#10;<p class="startli"><a href="http://en.wikipedia.org/wiki/SIMD">SIMD</a> instructions can perform parallel computation in modern CPUs. RapidJSON support Intel's SSE2/SSE4.2 to accelerate whitespace skipping. This improves performance of parsing indent formatted JSON. Define <span class="tt">RAPIDJSON_SSE2</span> or <span class="tt">RAPIDJSON_SSE42</span> macro to enable this feature. However, running the executable on a machine without such instruction set support will make it crash.</p>&#10;</li>&#10;<li><p class="startli">Does it consume a lot of memory?</p>&#10;<p class="startli">The design of RapidJSON aims at reducing memory footprint.</p>&#10;<p class="startli">In the SAX API, <span class="tt">Reader</span> consumes memory portional to maximum depth of JSON tree, plus maximum length of JSON string.</p>&#10;<p class="startli">In the DOM API, each <span class="tt">Value</span> consumes exactly 16/24 bytes for 32/64-bit architecture respectively. RapidJSON also uses a special memory allocator to minimize overhead of allocations.</p>&#10;</li>&#10;<li><p class="startli">What is the purpose of being high performance?</p>&#10;<p class="startli">Some applications need to process very large JSON files. Some server-side applications need to process huge amount of JSONs. Being high performance can improve both latency and throuput.
