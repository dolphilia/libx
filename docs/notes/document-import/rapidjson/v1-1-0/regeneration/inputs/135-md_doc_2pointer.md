<div class="contents rapidjson-document">&#10;<div class="textblock"><p><a class="anchor" id="autotoc_md46"></a></p>&#10;<p>(This feature was released in v1.1.0)</p>&#10;<p>JSON Pointer is a standardized (<a href="https://tools.ietf.org/html/rfc6901">RFC6901</a>) way to select a value inside a JSON Document (DOM). This can be analogous to XPath for XML document. However, JSON Pointer is much simpler, and a single JSON Pointer only pointed to a single value.</p>&#10;<p>Using RapidJSON's implementation of JSON Pointer can simplify some manipulations of the DOM.</p>&#10;<h1 class="doxsection"><a class="anchor" id="JsonPointer"></a>&#10;JSON Pointer</h1>&#10;<p>A JSON Pointer is a list of zero-to-many tokens, each prefixed by <span class="tt">/</span>. Each token can be a string or a number. For example, given a JSON: </p><div class="fragment"><div class="line">{</div>&#10;<div class="line">    "foo" : ["bar", "baz"],</div>&#10;<div class="line">    "pi" : 3.1416</div>&#10;<div class="line">}</div>&#10;</div><!-- fragment --><p>The following JSON Pointers resolve this JSON as:</p>&#10;<ol type="1">&#10;<li><span class="tt">"/foo"</span> → <span class="tt">[ "bar", "baz" ]</span></li>&#10;<li><span class="tt">"/foo/0"</span> → <span class="tt">"bar"</span></li>&#10;<li><span class="tt">"/foo/1"</span> → <span class="tt">"baz"</span></li>&#10;<li><span class="tt">"/pi"</span> → <span class="tt">3.1416</span></li>&#10;</ol>&#10;<p>Note that, an empty JSON Pointer <span class="tt">""</span> (zero token) resolves to the whole JSON.</p>&#10;<h1 class="tt">Pointer::Get()</span> or <span class="tt">GetValueByPointer()</span> function does not modify the DOM. If the tokens cannot match a value in the DOM, it returns <span class="tt">nullptr</span>. User can use this to check whether a value exists.</p>&#10;<p>Note that, numerical tokens can represent an array index or member name. The resolving process will match the values according to the types of value.</p>&#10;<div class="fragment"><div class="line">{</div>&#10;<div class="line">    "0" : 123,</div>&#10;<div class="line">    "1" : [456]</div>&#10;<div class="line">}</div>&#10;</div><!-- fragment --><ol type="1">&#10;<li><span class="tt">"/0"</span> → <span class="tt">123</span></li>&#10;<li><span class="tt">"/1/0"</span> → <span class="tt">456</span></li>&#10;</ol>&#10;<p>The token <span class="tt">"0"</span> is treated as member name in the first pointer. It is treated as an array index in the second pointer.</p>&#10;<p>The other functions, including <span class="tt">Create()</span>, <span class="tt">GetWithDefault()</span>, <span class="tt">Set()</span> and <span class="tt">Swap()</span>, will change the DOM. These functions will always succeed. They will create the parent values if they do not exist. If the parent values do not match the tokens, they will also be forced to change their type. Changing the type also mean fully removal of that DOM subtree.</p>&#10;<p>Parsing the above JSON into <span class="tt">d</span>,</p>&#10;<div class="fragment"><div class="line">SetValueByPointer(d, <span class="stringliteral">"1/a"</span>, 789); <span class="comment">// { "0" : 123, "1" : { "a" : 789 } }</span></div>&#10;</div><!-- fragment --><h2 class="doxsection"><a class="anchor" id="autotoc_md47"></a>&#10;Resolving Minus Sign Token</h2>&#10;<p>Besides, <a href="https://tools.ietf.org/html/rfc6901">RFC6901</a> defines a special token <span class="tt">-</span> (single minus sign), which represents the pass-the-end element of an array. <span class="tt">Get()</span> only treats this token as a member name '"-"'.
