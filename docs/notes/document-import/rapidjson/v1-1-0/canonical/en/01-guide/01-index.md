It was inspired by <a href="http://rapidxml.sourceforge.net/">RapidXml</a>.</p>&#10;<ul>&#10;<li>RapidJSON is <b>small</b> but <b>complete</b>. It supports both SAX and DOM style API. The SAX parser is only a half thousand lines of code.</li>&#10;<li>RapidJSON is <b>fast</b>. Its performance can be comparable to <span class="tt">strlen()</span>. It also optionally supports SSE2/SSE4.2 for acceleration.</li>&#10;<li>RapidJSON is <b>self-contained</b> and <b>header-only</b>. It does not depend on external libraries such as BOOST. It even does not depend on STL.</li>&#10;<li>RapidJSON is <b>memory-friendly</b>. Each JSON value occupies exactly 16 bytes for most 32/64-bit machines (excluding text string). By default it uses a fast memory allocator, and the parser allocates memory compactly during parsing.</li>&#10;<li>RapidJSON is <b>Unicode-friendly</b>. It supports UTF-8, UTF-16, UTF-32 (LE &amp; BE), and their detection, validation and transcoding internally. For example, you can read a UTF-8 file and let RapidJSON transcode the JSON strings into UTF-16 in the DOM. It also supports surrogates and "\u0000" (null character).</li>&#10;</ul>&#10;<p>More features can be read <a class="el" href="/docs/rapidjson/v1-1-0/en/01-guide/02-features/" title="Features">here</a>.</p>&#10;<p>JSON(JavaScript Object Notation) is a light-weight data exchange format. RapidJSON should be in fully compliance with RFC7159/ECMA-404, with optional support of relaxed syntax. More information about JSON can be obtained at</p><ul>&#10;<li><a href="http://json.org/">Introducing JSON</a></li>&#10;<li><a href="http://www.ietf.org/rfc/rfc7159.txt">RFC7159: The JavaScript Object Notation (JSON) Data Interchange Format</a></li>&#10;<li><a href="http://www.ecma-international.org/publications/standards/Ecma-404.htm">Standard ECMA-404: The JSON Data Interchange Format</a></li>&#10;</ul>&#10;<h2 class="doxsection"><a class="anchor" id="autotoc_md3"></a>&#10;Highlights in v1.1 (2016-8-25)</h2>&#10;<ul>&#10;<li>Added <a class="el" href="/docs/rapidjson/v1-1-0/en/01-guide/08-pointer/" title="Pointer">JSON Pointer</a></li>&#10;<li>Added <a class="el" href="/docs/rapidjson/v1-1-0/en/01-guide/09-schema/" title="Schema">JSON Schema</a></li>&#10;<li>Added <a class="el" href="/docs/rapidjson/v1-1-0/en/01-guide/04-dom/" title="DOM">relaxed JSON syntax</a> (comment, trailing comma, NaN/Infinity)</li>&#10;<li>Iterating array/object with <a class="el" href="/docs/rapidjson/v1-1-0/en/01-guide/03-tutorial/" title="Tutorial">C++11 Range-based for loop</a></li>&#10;<li>Reduce memory overhead of each <span class="tt">Value</span> from 24 bytes to 16 bytes in x86-64 architecture.</li>&#10;</ul>&#10;<p>For other changes please refer to <a class="el" href="/docs/rapidjson/v1-1-0/en/02-reference/128-md__c_h_a_n_g_e_l_o_g/" title="Change Log">change log</a>.</p>&#10;<h2 class="doxsection"><a class="anchor" id="autotoc_md4"></a>&#10;Compatibility</h2>&#10;<p>RapidJSON is cross-platform. Some platform/compiler combinations which have been tested are shown as follows.</p><ul>&#10;<li>Visual C++ 2008/2010/2013 on Windows (32/64-bit)</li>&#10;<li>GNU C++ 3.8.x on Cygwin</li>&#10;<li>Clang 3.4 on Mac OS X (32/64-bit) and iOS</li>&#10;<li>Clang 3.4 on Android NDK</li>&#10;</ul>&#10;<p>Users can build and run the unit tests on their platform/compiler.</p>&#10;<h2 class="doxsection"><a class="anchor" id="autotoc_md5"></a>&#10;Installation</h2>&#10;<p>RapidJSON is a header-only C++ library. Just copy the <span class="tt">include/rapidjson</span> folder to system or project's include path.</p>&#10;<p>RapidJSON uses following software as its dependencies:</p><ul>&#10;<li><a href="https://cmake.org/">CMake</a> as a general build tool</li>&#10;<li>(optional)<a href="http://www.doxygen.org">Doxygen</a> to build documentation</li>&#10;<li>(optional)<a href="https://github.com/google/googletest">googletest</a> for unit and performance testing</li>&#10;</ul>&#10;<p>To generate user documentation and run tests please proceed with the steps below:</p>&#10;<ol type="1">&#10;<li>Execute <span class="tt">git submodule update --init</span> to get the files of thirdparty submodules (google test).</li>&#10;<li>Create directory called <span class="tt">build</span> in rapidjson source directory.</li>&#10;<li>Change to <span class="tt">build</span> directory and run <span class="tt">cmake ..</span> command to configure your build. Windows users can do the same with cmake-gui application.</li>&#10;<li>On Windows, build the solution found in the build directory. On Linux, run <span class="tt">make</span> from the build directory.</li>&#10;</ol>&#10;<p>On successfull build you will find compiled test and example binaries in <span class="tt">bin</span> directory. The generated documentation will be available in <span class="tt">doc/html</span> directory of the build tree. To run tests after finished build please run <span class="tt">make&#10;test</span> or <span class="tt">ctest</span> from your build tree. You can get detailed output using <span class="tt">ctest&#10;-V</span> command.</p>&#10;<p>It is possible to install library system-wide by running <span class="tt">make install</span> command from the build tree with administrative privileges. This will install all files according to system preferences.
