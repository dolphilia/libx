<div class="contents rapidjson-document">&#10;<div class="textblock"><p><a class="anchor" id="autotoc_md30"></a></p>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md31"></a>全般</h1>&#10;<ul>&#10;<li>クロスプラットフォーム<ul>&#10;<li>コンパイラー：Visual Studio、gcc、clangなど。</li>&#10;<li>アーキテクチャー：x86、x64、ARMなど。</li>&#10;<li>オペレーティングシステム：Windows、Mac OS X、Linux、iOS、Androidなど。</li>&#10;</ul></li>&#10;<li>簡単な導入<ul>&#10;<li>ヘッダーファイルだけのライブラリーです。ヘッダーをプロジェクトへコピーするだけで利用できます。</li>&#10;</ul></li>&#10;<li>自己完結し、依存関係は最小限<ul>&#10;<li>STLやBOOSTなどは使用しません。</li>&#10;<li>インクルードするのは<span class="tt">&lt;cstdio&gt;</span>、<span class="tt">&lt;cstdlib&gt;</span>、<span class="tt">&lt;cstring&gt;</span>、<span class="tt">&lt;inttypes.h&gt;</span>、<span class="tt">&lt;new&gt;</span>、<span class="tt">&lt;stdint.h&gt;</span>だけです。</li>&#10;</ul></li>&#10;<li>C++の例外やRTTIを使用しません。</li>&#10;<li>高性能<ul>&#10;<li>テンプレートとインライン関数を使い、関数呼び出しのオーバーヘッドを減らします。</li>&#10;<li>最適化したGrisu2と浮動小数点数の解析処理を内部に実装しています。</li>&#10;<li>SSE2/SSE4.2への対応を任意で有効にできます。</li>&#10;</ul></li>&#10;</ul>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md32"></a>標準への準拠</h1>&#10;<ul>&#10;<li>RapidJSONはRFC4627/ECMA-404に完全に準拠することを目指しています。</li>&#10;<li>JSON Pointer（RFC6901）に対応。</li>&#10;<li>JSON Schema Draft v4に対応。</li>&#10;<li>Unicodeのサロゲートに対応。</li>&#10;<li>ヌル文字（<span class="tt">"\u0000"</span>）に対応。<ul>&#10;<li>たとえば、<span class="tt">["Hello\u0000World"]</span>を解析し、適切に扱えます。文字列の長さを取得・設定するAPIがあります。</li>&#10;</ul></li>&#10;<li>任意で緩和された構文に対応。<ul>&#10;<li>単一行（<span class="tt">// ...</span>）と複数行（<span class="tt">/* ... */</span>）のコメント（<span class="tt">kParseCommentsFlag</span>）。</li>&#10;<li>オブジェクトや配列の末尾のカンマ（<span class="tt">kParseTrailingCommasFlag</span>）。</li>&#10;<li><span class="tt">NaN</span>、<span class="tt">Inf</span>、<span class="tt">Infinity</span>、<span class="tt">-Inf</span>、<span class="tt">-Infinity</span>を<span class="tt">double</span>値として扱います（<span class="tt">kParseNanAndInfFlag</span>）。</li>&#10;</ul></li>&#10;<li><a href="http://github.com/miloyip/rapidjson/blob/master/doc/npm.md">NPMに対応</a>。</li>&#10;</ul>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md33"></a>Unicode</h1>&#10;<ul>&#10;<li>リトルエンディアンとビッグエンディアンを含むUTF-8、UTF-16、UTF-32エンコーディングに対応。<ul>&#10;<li>これらのエンコーディングを入出力ストリームとメモリー内の表現に使用します。</li>&#10;</ul></li>&#10;<li>入力ストリームのエンコーディングの自動検出に対応。</li>&#10;<li>エンコーディング間の変換を内部で処理できます。<ul>&#10;<li>たとえば、UTF-8ファイルを読み、DOM内のJSON文字列をRapidJSONでUTF-16へ変換できます。</li>&#10;</ul></li>&#10;<li>エンコーディングの妥当性検証を内部で処理できます。<ul>&#10;<li>たとえば、UTF-8ファイルを読み、すべてのJSON文字列が妥当なUTF-8バイト列かどうかをRapidJSONで確認できます。</li>&#10;</ul></li>&#10;<li>独自の文字型に対応。<ul>&#10;<li>既定の文字型は、UTF8では<span class="tt">char</span>、UTF16では<span class="tt">wchar_t</span>、UTF32では<span class="tt">uint32_t</span>です。</li>&#10;</ul></li>&#10;<li>独自のエンコーディングに対応。</li>&#10;</ul>&#10;<h1 class="doxsection"><a Use Reader for UTF8 encoding and default allocator.">rapidjson::GenericReader</a></span>）を使って実装されています。SAXの方が高速ですが、DOMの方が使いやすい場合もあります。利用場面に応じて選択できます。</li>&#10;</ul></li>&#10;</ul>&#10;<h1 class="doxsection"><a class="anchor" situ</em>解析に対応。<ul>&#10;<li>元のJSON内で文字列値をその場で解析し、DOMはそれらの文字列のアドレスを指します。</li>&#10;<li>通常の解析より高速です。文字列用のメモリー確保が不要で、エスケープを含まなければコピーも不要です。キャッシュにも適しています。</li>&#10;</ul></li>&#10;<li>JSONの数値型として、32ビット・64ビットの符号付き整数・符号なし整数と<span class="tt">double</span>に対応。</li>&#10;<li>入力ストリーム中の複数のJSONの解析に対応（<span class="tt">kParseStopWhenDoneFlag</span>）。</li>&#10;<li>エラー処理<ul>&#10;<li>解析に失敗したときに、広範なエラーコードを提供します。</li>&#10;<li>エラーメッセージのローカライズに対応。</li>&#10;</ul></li>&#10;</ul>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md36"></a>DOM（Document）</h1>&#10;<ul>&#10;<li>RapidJSONは、変換時に数値の範囲を確認します。</li>&#10;<li>文字列リテラルの最適化<ul>&#10;<li>コピーせず、ポインターだけを保存します。</li>&#10;</ul></li>&#10;<li>「短い」文字列の最適化<ul>&#10;<li>短い文字列は、追加のメモリー確保をせずに<span class="tt">Value</span>内部へ保存します。</li>&#10;<li>UTF-8文字列では、32ビット環境で最大11文字、64ビット環境で21文字（x86-64では13文字）。</li>&#10;</ul></li>&#10;<li>任意で<span class="tt">std::string</span>に対応（<span class="tt"><a class="el" std::string.">RAPIDJSON_HAS_STDSTRING</a>=1</span>を定義）。</li>&#10;</ul>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md37"></a>生成</h1>&#10;<ul>&#10;<li>改行とインデントを加える<span class="tt"><a spacing.">rapidjson::PrettyWriter</a></span>に対応。</li>&#10;</ul>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md38"></a>ストリーム</h1>&#10;<ul>&#10;<li>出力JSONを文字列として保存する<span class="tt"><a href="/docs/rapidjson/v1-1-0/en/02-reference/024-classrapidjson_1_1_file_read_stream/" title="File byte stream for input using fread().">rapidjson::FileReadStream</a></span>と<span class="tt"><a class="el" href="/docs/rapidjson/v1-1-0/en/02-reference/026-classrapidjson_1_1_file_write_stream/" title="Wrapper of C file stream for input using fread().">rapidjson::FileWriteStream</a></span>に対応。</li>&#10;<li>独自のストリームに対応。</li>&#10;</ul>&#10;<h1 class="doxsection"><a class="anchor" id="autotoc_md39"></a>メモリー</h1>&#10;<ul>&#10;<li>DOMのメモリーオーバーヘッドを最小化します。<ul>&#10;<li>大半の32ビット・64ビット環境で、各JSON値は正確に16/20バイトを占めます（文字列のテキストを除く）。</li>&#10;</ul></li>&#10;<li>高速な既定のアロケーターに対応。<ul>&#10;<li>スタックに基づくアロケーターです。順番に確保し、個別の確保領域の解放を禁止するため、解析に適しています。</li>&#10;<li>事前に確保したバッファーを指定できます。（CRTによるメモリー確保を一度も行わずに複数のJSONを解析できる場合があります。）</li>&#10;</ul></li>&#10;<li>標準のCRT（Cランタイム）アロケーターに対応。</li>&#10;<li>独自のアロケーターに対応。</li>&#10;</ul>&#10;<h1
