# TOML 1.1.0 の保守と再開

公開仕様全文、ABNF 全文、公開仕様と仕様リポジトリの両 MIT 原文を3ページの英日組で扱う。固定入力の正本は SOURCE_LOCK.json、収録境界は CONTENT_MAP.json。第109の別工程全文レビューと、第110・111の表示・機械検査を区別する。

上流監視では、公式サイトの版一覧・1.1.0本文・公式仕様リポジトリのリリース、仕様サイトと仕様リポジトリの文書・ライセンス差分を確認する。各入力は SOURCE_LOCK.json の固定コミットと比較し、本文・文法・通知・参照・生成設定の変更を分類する。新版は新しい Libx 版として追加し、固定1.1.0を黙って置換しない。

再開時は OPERATIONS と実ファイルの SHA-256 を照合する。定本再生成は `node scripts/importers/import-toml-1.1.0.mjs --check`、日本語の構造・リンクは `node scripts/validate-translated-content.mjs --project=toml --version=v1-1-0 --target=ja` で確認できる。通常の依存関係準備後は `pnpm --filter apps-toml check:content` が両検査を実行する。

内容が変われば該当ページと依存ページの全文レビューを失効させ、別工程で原文・定本・日本語を全て確認する。設定や共有UIが変われば影響する機械・表示検査を再実行する。定本・初稿・レビュー済み訳文の保存版は上書きせず、新しい証拠を残す。

共有ルートには Awesome とユーザーの未完了変更がある。ビルドと公開候補は隔離環境で作り、新規アプリと対象の設定差分だけを反映する。第111は共有側の3ファイルの既存変更を検証環境へ反映し、そのファイルを共有側へコピーしていない。検証範囲は TOML とランディングページで、全既存アプリのビルド完了を意味しない。

外部公開は未承認。公開する場合は対象を限定したクリーンな候補から統合 Cloudflare Pages の成果物を生成し、配信IDと成果物ハッシュを照合する。Workersと定期実行設定は使わない。
