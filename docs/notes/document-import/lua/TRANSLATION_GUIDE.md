# Lua日本語翻訳の用語・表記規則

- 状態: 代表ページ試訳・部分翻訳検査を経て確定
- 適用対象: Lua 5.5英語定本から日本語への逐次翻訳
- 確定日: 2026-08-11

## 1. 基本方針

1. 英語定本の意味、条件、例外、強度、順序を変えない。
2. コード、API識別子、文法記号、アンカー、URLは翻訳しない。
3. 説明文は自然な日本語にするが、要約・補筆・一般化を行わない。
4. Lua固有語は公式の表記を保持し、初出で必要な説明だけを訳文に含める。
5. 翻訳機、翻訳API、ローカル翻訳モデル、一括翻訳スクリプトを初稿作成に使わない。
6. 一ページずつ定本と照合し、構造検査後に完了とする。

## 2. 翻訳しないもの

- LuaコードとCコード
- `lua_*`、`luaL_*`、`LUA_*`、`LUAL_*`の識別子
- 標準ライブラリ・関数名（例: `string.gsub`、`table.insert`）
- 型、マクロ、構造体、ヘッダーファイル名
- メタメソッド名（例: `__index`、`__gc`）
- Luaキーワード、演算子、リテラル
- BNFの非終端記号と生成規則
- スタック効果表記（例: `[-1, +0, e]`）
- コマンド名、オプション、環境変数、パス
- HTMLアンカー、Markdownリンク先、Frontmatterキー、`licenseSource`

## 4. 規範表現

| 英語 | 基本的な扱い |
| --- | --- |
| must | 「〜しなければならない」 |
| must not | 「〜してはならない」 |
| should | 「〜するべきである」または文脈に応じた推奨 |
| should not | 推奨しないことを明示する |
| may | 許可・可能性を文脈で区別する |
| can | 能力・可能性を文脈で区別する |
| always | 「常に」を省略しない |
| never | 「決して〜ない」を弱めない |
| only if | 必要条件の向きを変えない |
| unless | 否定条件の作用範囲を照合する |

undefined、unspecified、implementation-defined等は同じ「未定義」にまとめず、定本の区別を維持する。

## 5. Lua・C API固有のレビュー

- スタックのpop・push数とエラー記号を保持する。
- インデックスの正負、疑似インデックス、有効期間を保持する。
- 関数が返す値の数と順序を保持する。
- yield可能性、エラー、メモリー割り当て、long jumpの条件を保持する。
- GCモード、弱参照、finalizer、to-be-closed変数の順序を保持する。
- バイナリ互換性、再コンパイル条件、版の非互換性を弱めない。
- `nil`、`false`、absence、no valueの違いを省略しない。

- 本文は常体を基本とする。

## 8. 部分翻訳中の内部リンク

- 翻訳先ページがまだ存在しない間は、リンク先を英語定本の`/en/` URLのまま保つ。
- 対応する日本語ページを配置した時点で、参照元のリンクを`/ja/`へ切り替える。
- 全ページ配置後に内部リンクを一括同期し、英語URL残存数とリンク切れが0件であることを確認する。
- 外部URL、フラグメント、スラッグは変更しない。
