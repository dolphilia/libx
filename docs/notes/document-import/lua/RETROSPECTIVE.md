# Lua文書インポート・翻訳パイロット総括

- 総括日: 2026-08-11
- 対象: Lua 5.5.1公式文書の取得、Markdown化、英語定本化、日本語翻訳、Preview確認
- 公開状態: Cloudflare Pages Production公開済み
- 継続改善: 独立した第三者校閲、実機・複数ブラウザでのアクセシビリティ確認

## 1. 結果

Lua 5.5.1の公式tarballをSHA-256で固定し、同梱のリファレンスマニュアル、README、`lua(1)`、`luac(1)`と、取得時点の公式既知問題を56ページへ整理した。英語定本56ページと同一構造の日本語56ページを人手で逐次翻訳した。

| 項目 | 結果 |
| --- | --- |
| 固定入力 | `lua-5.5.1.tar.gz`、SHA-256一致 |
| 英語定本 | 56/56ページ |
| 日本語翻訳 | 56/56ページ、欠落0、余分0 |
| 上流アンカー | 538件を移行 |
| 内部リンク検査 | 1,164件、エラー0 |
| Luaサイト | 116ページ生成 |
| 統合成果物 | 799ファイル、36.65 MiB |
| Preview | 主要URL 200、未知URL 404、帰属表示を確認 |

これにより、Doxygenとは異なる「一つの大きな手書きHTML、manページ、数百の明示アンカー」を持つ文書でも、固定版の取得から多言語公開直前まで同じ基本工程を適用できた。

## 2. GLFWでもLuaでも成立した工程

- 正式版、取得URL、ハッシュ、ライセンスを本文処理前に固定する。
- 原資料・中間物・検証済みコンテンツ・判断記録を分離する。
- 上流物を採用、統合、検査参照、外部参照、除外へ分類する。
- 公開先へ直接書かず、一時生成、検査、置換の順にする。
- 英語定本と翻訳を同じカテゴリ・スラッグに置きつつ、途中の言語欠落を許容する。
- コード、インラインコード、URL、アンカー、識別子、内部リンクを機械比較する。
- サイト単位の個別・選択的ビルドを反復に使い、公開前だけ統合ビルドする。
- 帰属、原文、ライセンスを設定の一か所から全ページへ表示する。
- PreviewをProductionと分け、管理者の明示承認を公開条件にする。

二例で再現したため、安全な出力、共通コンテンツ検査、欠落許容、サイト固有`check:content`はlibxの共通基盤として妥当である。

## 3. 上流形式ごとに残すべき処理

GLFWではDoxygen命令、生成HTML、グループAPI、ソース断片、画像の照合が中心だった。Luaでは巨大な手書きHTMLの分割、明示アンカーの移行、manマクロ変換、ヘッダーとの宣言照合、README・manual・manを混ぜない判断が中心だった。

変換アダプターとページ分割は上流形式固有のまま保ち、共通APIへ早期に押し込まない。共通化するのは取得証拠、安全出力、構造・リンク検査、進捗・公開ゲートである。

## 4. Luaで得た追加知見

### 4.1 取得直前の正式版再確認が必要である

初期選定時の5.5.1はRCだったが、正式取得時には正式版へ移っていた。本文処理前だけ版変更を許す規則が機能した。長期作業でも「最新」を追従し続けず、固定後は別版として扱う。

### 4.2 ページマップは人の判断を記録する正本になる

1シンボル1ページを避け、通常節は上流単位、巨大な§4.6と§5.1だけを安定した名前範囲に分けた。56ページという結果は機械的な唯一解ではなく、表示負荷、更新差分、翻訳単位、ファイル数の均衡である。境界をコード化したページマップが再生成可能性を支えた。

### 4.3 部分翻訳時と全訳後ではリンク方針が変わる

翻訳先がない間は英語URLを維持し、全訳後だけ日本語URLへ同期した。存在しない翻訳URLを先に生成しないために有効だった。一方、プロジェクト別同期スクリプトの重複は共通化候補になった。

### 4.4 厳密な不変要素比較は省略も検出する

インラインコードを値と出現数で照合したことで、日本語として自然に見える反復省略も検出できた。規範文書では有用だが、表現の自由を不必要に狭める場合もあるため、コード・API・条件の保持を確認する補助として使い、人が原文を照合する。

### 4.5 翻訳生成の自動化を急ぐ必要はない

GLFWでの翻訳サービス・ローカルモデル評価を踏まえ、Luaでは機械訳を経由せず一ページずつ翻訳した。規範表現、否定、条件、API名を保つには、現時点では人による定本照合が必要である。自動化は生成より先に、差分、構造、リンク、危険箇所の提示へ使う。

### 4.6 ブラウザ確認はビルド成功と異なる欠陥を見つける

ブラウザ確認で、`v5-5-1`のようなハイフン付き版IDをサイドバー先読みが認識せず、存在しない`v1`を要求する問題を発見した。また、前後移動の走査が`.mdx`だけを対象とし、Luaの`.md`ページではナビゲーションが消えていた。いずれもビルドとコンテンツ検査だけでは見つからなかった。

### 4.7 記録の進捗重複は二例目でも陳腐化した

実ファイルが56/56になった後も計画書とREADMEに28/56が残った。GLFWでも同じ問題が起きたため、進捗の単一正本と自動検査は推測ではなく、二例で実証された要件である。

## 5. 表示・公開検証

ローカルでは入口、完全な構文、デバッグC API、文字列操作、`lua(1)`、既知問題、404を確認した。言語切替、サイドバー、前後移動、390×844の表示、コード領域の横スクロール、帰属、コンソールエラーなしも確認した。

キーボードについては、リンク・ボタン・`summary`がネイティブのフォーカス可能要素であり、ラベルを持つことをDOM上で確認した。ただし自動操作環境ではTabによる実フォーカス移動を再現できなかったため、実機での完全なキー順序確認と独立した第三者校閲は今後も推奨する。

Cloudflare Pages Previewでは、ルート、Lua日本語入口、文字列操作、サイドバーJSONが200、未知URLが独自404を返すことを確認した。管理者の明示承認後、同じ検証済み成果物をProductionへ公開した。

## 6. 汎用ガイドへ反映する知見

次回の改訂候補は次のとおりである。

1. 正式取得直前の版再確認と、固定後に自動追従しない規則。
2. 部分翻訳中は実在するページだけへリンクし、全訳後に言語URLを同期する工程。
3. `.md`と`.mdx`の両方をナビゲーション・検査対象にすること。
4. ハイフン区切りの安全な版IDをサイドバー・成果物名まで一貫して扱うこと。
5. ブラウザで200・404、サイドバー、前後移動、帰属、コンソールと失敗リクエストを確認すること。
6. 進捗数を実ファイル集合から生成し、複数文書へ手書きしないこと。

## 7. 結論

Luaパイロットにより、libxの基本方針はDoxygen以外の公式文書にも適用できた。共通化すべき中心は文章変換そのものではなく、固定版の証拠、安全な生成、言語欠落、構造・リンク検査、サイト単位のビルド、Previewと承認の公開ゲートである。

次に優先すべきなのは、訳文生成の自動化ではなく、進捗の単一正本、URL同期、ブラウザ・Previewスモーク、上流更新差分とレビュー失効の自動化である。
