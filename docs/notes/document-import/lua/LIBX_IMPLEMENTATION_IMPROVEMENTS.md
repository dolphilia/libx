# Luaパイロットから得たlibx実装改善案

- 作成日: 2026-08-11
- 対象: libx本体、外部文書インポート、翻訳検査、表示・公開検証
- 位置付け: 実装済み事項と次期改善候補の整理。候補はこの文書だけでは実装承認を意味しない。

## 1. Luaパイロット中に実装した改善

### 1.1 Lua固有インポータとページマップ

巨大な手書きHTML、README、manページ、明示アンカーを56ページへ再現可能に変換した。共通の安全出力を使い、`--source`、`--output`、`--check`、`--dry-run`、入力ハッシュ、検査後置換を実装した。

### 1.2 共通コンテンツ検査の二例目適用

定本・翻訳のファイル集合、Frontmatter、見出し、コード、インラインコード、アンカー、識別子、内部リンクをLuaでも検査した。最終状態は英日56/56、内部リンク1,164件、エラー0である。

### 1.3 全訳後の日本語URL同期

部分翻訳中の英語リンクを、全件成立後に日本語URLへ一括変換するスクリプトを追加した。存在しない翻訳ページへ先行してリンクしない運用を再現可能にした。

### 1.4 ハイフン付き版IDのサイドバー先読み修正

`DocLayout.astro`が`v1`形式しか認識せず、`v5-5-1`で誤ったサイドバーJSONを先読みしていた。全サイトとテンプレートで`v`に続く複数の数字区間を認識するよう修正し、テンプレート回帰検査を追加した。

### 1.5 `.md`ページの前後移動修正

共有`content-utils`の走査が`.mdx`だけを対象としていたため、Luaの`.md`ページに前後移動が生成されなかった。`.md`と`.mdx`の両方を対象に修正し、回帰検査を追加した。

## 2. 優先度P0: 次のパイロット前に実装する候補

### 2.1 進捗の単一正本と陳腐化検査

GLFWとLuaの両方で、実ファイル数と計画書・READMEの進捗がずれた。英語・翻訳ファイル集合、リンク数、レビュー状態を一つの機械可読マニフェストから生成し、手書きの進捗値が異なる場合はCIで失敗させる。

最低出力は版、定本数、言語別翻訳数、欠落、余分、内部リンク、レビュー状態とする。公開ランタイム設定の`project.config.jsonc`とは分離する。

### 2.2 言語URL同期を共通コマンドへ昇格する

GLFWとLuaで、全訳後に内部URLの言語区間を同期する必要が再現した。プロジェクト別の文字列置換を増やさず、設定、対象版、定本言語、翻訳言語、実在ページ集合から安全に同期・検査する共通コマンドへする。

`--check`と`--dry-run`を持ち、存在しない翻訳先、外部URL、コード領域、アンカーを変更しないことをテストする。

### 2.3 サイト別ブラウザ・Previewスモークの宣言化

サイトごとに代表URLを宣言し、入口、主要カテゴリ、最大ページ、言語・版切替、サイドバー、前後移動、帰属、404、コンソールエラー、失敗リクエストを共通テストで確認する。PreviewではHTTP 200・404と配信されたJSON・アセットも検査する。

キーボード順序と主要アクセシビリティ検査も自動化し、手動確認で再現できなかった項目を曖昧に完了扱いしない。

### 2.4 実行時挙動を検証する回帰テスト

今回追加したテンプレートの静的ソース検査は軽量だが、正規表現の存在だけでは生成URLや前後関係を保証しない。次を小さいfixtureの実ビルドで検証する。

- `v5-5-1`のサイドバー先読みURLが実在する。
- `.md`と`.mdx`の両方で前後リンクが生成される。
- 翻訳0件・部分・全件でも存在しない切替リンクを出さない。

## 3. 優先度P1: 運用を軽くする改善候補

### 3.1 インポートパイロットのスキャフォールド

計画、取得元、対応表、翻訳ガイド、翻訳計画、作業ログ、レビュー表、総括、実装改善案と`.tmp`作業領域を標準コマンドで作る。上流形式固有のページ分割や用語判断は生成しない。

### 3.2 上流更新差分と翻訳レビュー失効

入力ファイル、上流アンカー、生成ページ、ハッシュ、変換器版の対応から、追加・変更・削除・移動を報告する。変わった英語ページだけ対応翻訳を「再照合必要」に戻し、無関係な翻訳を再レビューしない。

### 3.3 サイト別成果物レポート

統合値だけでなく、サイト別のページ数、静的ファイル数、容量、最大ファイル、ビルド時間をJSONと人向け表で残す。ファイル数や時間が予算を超える場合は、サイト分割を検討する兆候として警告する。

### 3.4 外部リンク検査の分離

通常CIではURL構文、プロトコル、英日一致だけを決定的に検査する。公開前・定期検査ではHTTP到達性とリダイレクトを確認し、一時障害と恒久404を区別する。

### 3.5 インポータ変換品質の報告

Luaの定義リストや複雑なHTMLはMarkdown化後に意味を保っていても読みやすさの手直しが必要だった。未処理HTMLだけでなく、極端に長い段落、連続改行、空見出し、崩れやすい定義リストを候補として報告する。自動修正ではなく人の確認順を決める用途に限定する。

## 4. 優先度P2: 複数形式を見て判断する候補

### 4.1 共通のインポートマニフェスト

二例で、版、取得ハッシュ、ページ対応、変換器版、翻訳状態が必要になった。Frontmatterを肥大化させず、運用用サイドカーマニフェストを正本とする案をADRで比較する。

### 4.2 共通インポータAPIの境界

共通化してよいのは安全な出力、ハッシュ、差分、構造・リンク検査である。Doxygen変換とLua HTML・man変換はアダプターとして残す。三例目でも再現した変換契約だけを安定APIへ昇格する。

### 4.3 翻訳レビュー重点箇所の汎用報告

must、only if、unless、before、undefined、スタック効果、数値境界などを自然言語ノードから抽出し、定本照合の優先順位を示す。自動合否や自動翻訳には使わない。

## 5. 推奨実施順

1. 進捗マニフェストと文書陳腐化検査を実装する。
2. 言語URL同期を共通化する。
3. サイト別ブラウザ・Previewスモークを宣言化する。
4. `.md`／`.mdx`、ハイフン版ID、言語欠落を実ビルドfixtureで検査する。
5. パイロットのスキャフォールドと上流更新差分を追加する。
6. サイト別成果物レポート、外部リンク、変換品質報告を追加する。
7. 三例目の結果を踏まえて共通マニフェストとインポータAPIをADRで決める。

## 6. 現時点で実装しないもの

- 翻訳サービスやローカルモデルによる訳文の自動生成。
- 未翻訳本文を定本言語で黙って表示するフォールバック。
- 1 APIシンボル1ページへの機械的分割。
- 上流形式固有の変換を一つの汎用変換器へ統合すること。
- 管理者承認を省略したProduction自動公開。
