<article class="libuv-document" id="furo-main-content" role="main">&#10;<section id="file-system-operations">&#10;<span id="fs"></span><h1>File system operations<a class="headerlink" href="#file-system-operations" title="Permalink to this heading">¶</a></h1>&#10;<p>libuv provides a wide variety of cross-platform sync and async file system&#10;operations. All functions defined in this document take a callback, which is&#10;allowed to be NULL. If the callback is NULL the request is completed synchronously,&#10;otherwise it will be performed asynchronously.</p>&#10;<p>All file operations are run on the threadpool. See <a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/threadpool/#threadpool"><span class="std std-ref">Thread pool work scheduling</span></a> for information&#10;on the threadpool size.</p>&#10;<p>Starting with libuv v1.45.0, some file operations on Linux are handed off to&#10;<cite>io_uring &lt;https://en.wikipedia.org/wiki/Io_uring&gt;</cite> when possible. Apart from&#10;a (sometimes significant) increase in throughput there should be no change in&#10;observable behavior. Libuv reverts to using its threadpool when the necessary&#10;kernel features are unavailable or unsuitable. Starting with libuv v1.49.0 this&#10;behavior was reverted and Libuv on Linux by default will be using the threadpool&#10;again. In order to enable io_uring the <a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/loop/#c.uv_loop_t" title="uv_loop_t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv_loop_t</span></code></a> instance must be&#10;configured with the <code class="xref c c-type docutils literal notranslate"><span class="pre">UV_LOOP_USE_IO_URING_SQPOLL</span></code> option.</p>&#10;<div class="admonition note">&#10;<p class="admonition-title">Note</p>&#10;<p>On Windows <cite>uv_fs_*</cite> functions use utf-8 encoding.</p>&#10;</div>&#10;<section
