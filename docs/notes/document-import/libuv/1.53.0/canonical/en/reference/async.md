<article class="libuv-document" id="furo-main-content" role="main">&#10;<section id="uv-async-t-async-handle">&#10;<span id="async"></span><h1><a class="reference internal" href="#c.uv_async_t" title="uv_async_t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv_async_t</span></code></a> — Async handle<a class="headerlink" href="#uv-async-t-async-handle" title="Permalink to this heading">¶</a></h1>&#10;<p>Async handles allow the user to “wakeup” the event loop and get a callback&#10;called from another thread.</p>&#10;<div class="admonition note">&#10;<p class="admonition-title">Note</p>&#10;<p><a class="reference internal" href="#c.uv_async_send" title="uv_async_send"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_async_send()</span></code></a> and the <a class="reference internal" href="#c.uv_async_cb" title="uv_async_cb"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv_async_cb</span></code></a> invocation are&#10;sequentially consistent (seq_cst) operations for a given async handle: all&#10;memory accesses (reads and writes) made before <a class="reference internal" href="#c.uv_async_send" title="uv_async_send"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_async_send()</span></code></a> are&#10;visible to that callback.</p>&#10;</div>&#10;<div class="admonition warning">&#10;<p class="admonition-title">Warning</p>&#10;<p>libuv will coalesce calls to <a class="reference internal" href="#c.uv_async_send" title="uv_async_send"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_async_send()</span></code></a>, that is, not every&#10;call to it will yield an execution of the callback. For example: if&#10;<a class="reference internal" href="#c.uv_async_send" title="uv_async_send"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_async_send()</span></code></a> is called 5 times in a row before the callback is&#10;called, the callback will only be called once. If <a class="reference internal" href="#c.uv_async_send" title="uv_async_send"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_async_send()</span></code></a>&#10;is called again after the callback was called, it will be called again.&#10;However, since it is sequentially consistent, the values read or written in&#10;that callback will always be the same (or newer) as those read or written&#10;by the other thread.</p>&#10;</div>&#10;<div class="versionchanged">&#10;<p><span class="versionmodified changed">Changed in version 1.53.0: </span><a class="reference internal" href="#c.uv_async_send" title="uv_async_send"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv_async_send()</span></code></a> and <a class="reference internal" href="#c.uv_async_cb" title="uv_async_cb"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv_async_cb</span></code></a> are sequentially&#10;consistent. Prior to this version, any case where libuv might coalesce&#10;calls probably requires a full <cite>seq_cst</cite> fence before it for correctness.</p>&#10;</div>&#10;<section
