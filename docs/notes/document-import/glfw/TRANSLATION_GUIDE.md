# GLFW日本語翻訳の用語・表記規則

## 1. 翻訳方針

- 翻訳元の定本は`apps/glfw/src/content/docs/v3-5-1/en/`とする。
- 英語と日本語でカテゴリ、ファイル名、見出しアンカー、ページ順を同一にする。
- API識別子、Cコード、マクロ、型、数値、URL、HTMLアンカーは変更しない。
- `must`は「〜しなければならない」、`should`は「〜するべき」、`may`は文脈に応じて「〜してもよい／〜する場合がある」とし、規範の強さを落とさない。
- 原文を要約・補足しない。日本語として主語を補う必要がある場合も技術的条件を増減しない。
- 現段階では翻訳機、翻訳API、ローカル翻訳モデル、一括翻訳スクリプトを使用しない。
- `MANUAL_TRANSLATION_PLAN.md`の順序で一ページずつ翻訳し、同じ作業内で定本との原文照合まで行う。

## 3. 固有名詞・識別子

`GLFW`、`OpenGL`、`OpenGL ES`、`Vulkan`、`CMake`、`Wayland`、`X11`、`Win32`、`macOS`、`EGL`、`GLX`、`WGL`は原綴りを保持する。`glfwInit`、`GLFW_TRUE`、`GLFWwindow`のような識別子は文章中でも翻訳・空白挿入・大文字小文字変更を行わない。

## 4. 文体

- 本文は「です・ます」調を基本とする。
- APIリファレンスの短い定義は体言止めを許容する。
- 読者への操作指示は「〜してください」または技術的要件に応じて「〜する必要があります」とする。
- 原文のNote、Warning、Returns、Parameters、Errors、Thread safety、Since、See alsoは、それぞれ「注記」「警告」「戻り値」「引数」「エラー」「スレッドセーフ性」「導入バージョン」「関連項目」とする。

## 5. 一ページの翻訳後に行う必須検査

1. 英語と日本語のファイル集合が一致する。
2. コードフェンスの本数、言語、内容が一致する。
3. URL、HTMLアンカー、GLFW／Vulkan識別子が一致する。
4. 規範語、否定、プラットフォーム条件、戻り値、エラー条件を原文と照合する。
5. 用語表に反する表記揺れを検索する。

## 6. 判断に迷う場合

- 原文の一文を分割・統合すると条件の範囲が変わる場合は、原文の構造を優先する。
- `may`が許可か可能性か判断できない場合は、APIの説明、エラー条件、スレッドセーフ性、関連ガイドを確認する。
- 日本語を自然にするための補足が必要に見えても、定本にない技術説明は追加しない。
- 一つの訳に確定できない場合はページを完了扱いにせず、候補と論点を`WORK_LOG.md`へ記録する。
- 用語表を変更するときは、翻訳済みページへの影響を確認し、変更理由を記録する。
