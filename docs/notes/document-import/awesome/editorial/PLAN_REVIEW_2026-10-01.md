# Awesome全ページ編集計画のレビュー記録

実施日: 2026-10-01。対象: [Awesomeリスト全ページの編集と翻訳レビュー計画](../../../../plans/AWESOME_FULL_CONTENT_EDITORIAL_REVIEW_PLAN.md)。草稿保存後に同じCodexがレビューを1回実施し、以下を計画本文へ反映した。独立した別担当者によるレビューや、人手によるレビューではない。

## レビューで見つかった問題と修正

| 観点 | 草稿の不足 | 反映した修正 |
| --- | --- | --- |
| 英日で同時に起きる欠落 | 英日対応検査だけでは両方から消えた項目を検出できない | 編集前の全項目に位置・主リンク・入力ハッシュを含む安定IDを与え、全件の行先を照合する |
| 検査と編集の衝突 | Selfhostedの警告記号はインラインコードであり、文字化すると現行の英日コード一致条件と衝突する | 表示用トークンだけを記録付きで比較し、プログラムのコード等の厳格な検査を維持する |
| 見出しの変更 | 自動目次の修正だけでは従来アンカーへのリンクが壊れ得る | 既存IDと参照元を列挙し、必要な別名IDや参照更新を実施する |
| 全文レビューの証拠 | 全文を読むという指示だけでは長文の読み残しを検証できない | 節・項目IDの確認範囲と成果物ハッシュを保存し、範囲の欠落を検査する。省略された出力は未読とする |
| 案内ページの例外 | 全文収録と同じ完了条件ではmetadata-onlyに転載対象外の全文翻訳を要求してしまう | 案内の根拠と英日案内全文を確認する条件に分けた |
| 工程の実行順 | フェーズ1の完了にフェーズ2の編集済み成果物を要求する循環があった | 基盤では代表入力と編集fixtureを使い、パイロット完成後に全対象で再生成を検証する |
| 表示確認の漏れ | ビルドと代表確認だけでは全件の画像・目次・出典表示を保証できない | 全件HTML検査と、全子・両版・両言語および例外を含むブラウザー検証を区別した |
| スナップショットの意味 | 編集中の外部調査で最新の仕様やリンクを混ぜる余地があった | 固定原文を基準にし、補足調査・リンク修正の根拠を記録する方針を追加した |

## 再確認した事項

- 対象は実ファイルで英日1,037組、計2,074文書。最新672組と過去365組を独立に扱う。
- 最新版10組の部分調査と過去版2組の冒頭確認を、全文レビューと誤表示していない。
- 自動目次の既定対象はルート実装上H2/H3。レイアウトのフォールバック設定だけからH2のみと判断していない。
- ライセンスに関する語を含む通常項目、個々のツールの利用条件、Unicodeの教材例を一律削除しない。
- リスト自体のライセンス節は共通の出典表示へ集約し、証拠や必要な通知を失わない。
- 計画進行から翻訳・レビューまでCodexを使用し、GPT-6.1 Solを標準とする。ローカルLLMを前提にしない。
- 旧計画・過去のレビュー実績を今回の内容レビュー完了として継承しない。
- 既存の再import差分を無視せず、編集結果を再生成時に失わない工程がある。
- 今回は計画書と記録の作成まで。Awesome本文、コード、既存進捗JSON、外部配信は変更しない。

## 検証範囲

計画に引用したパス・表示実装・既存コマンドはリポジトリ内で確認した。計画と本記録をremarkで解析し、相対リンク16件の存在、各文書の単一H1、コードフェンスの対応、末尾空白がないこと、記載したコマンドのpackage.json登録を確認した。`git diff --check` も合格した。文書のみの変更であるため、アプリのビルド・実ブラウザー検証は今回は実施していない。これらは計画の実行時に行う。

全件の問題件数、各ページの最終的な例外、所要時間、パイプライン修正の詳細は今回の軽い調査だけでは確定できない。計画のフェーズ0〜2で確定し、台帳と実績に基づいて更新する。
