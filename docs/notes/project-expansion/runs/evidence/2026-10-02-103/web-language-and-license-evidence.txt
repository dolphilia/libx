L130: ##### MsgPack
L131: 
L132: MessagePack implementation for Arduino (compatible with other C++ apps)
L133: ###### Feature
L134: 
L135:   * one-line [serialize / deserialize] for almost all standard type of C++ same as cite9†msgpack-c†github.com L136:   * support custom class [serialization / deserialization]
L137:   * support working with cite10†ArduinoJSON†github.com L138:   * one-line [save / load] between custom serializable MsgPack class and JSON file
L139:   * one-line [save / load] custom serializable MsgPack class [to / from] EEPROM
L140: ###### Typical Usage
L141: This library is only for serialize / deserialize. To send / receive serialized data with `Stream` class, please use cite11†MsgPacketizer†github.com .
L142: 
L143:     #include <MsgPack.h>
L144: 
L145:     // input to msgpack
L146:     int i = 123;
L147:     float f = 1.23;
L148:     MsgPack::str_t s = "str"; // std::string or String
L149:     MsgPack::arr_t<int> v {1, 2, 3}; // std::vector or arx::vector
L150:     MsgPack::map_t<String, float> m {{"one", 1.1}, {"two", 2.2}, {"three", 3.3}}; // std::map or arx::map
L151: 
L152:     // output from msgpack
L153:     int ri;
L154:     float rf;
L155:     MsgPack::str_t rs;
L156:     MsgPack::arr_t<int> rv;
L157:     MsgPack::map_t<String, float> rm;
L158: 
L159:     void setup() {
L160:         delay(2000);
L161:         Serial.begin(115200);
L162:         Serial.println("msgpack test start");
L163: 
L164:         // serialize to msgpack
L165:         MsgPack::Packer packer;
L166:         packer.serialize(i, f, s, v, m);
L167: 
L168:         // deserialize from msgpack
L169:         MsgPack::Unpacker unpacker;
L170:         unpacker.feed(packer.data(), packer.size());
L171:         unpacker.deserialize(ri, rf, rs, rv, rm);
L172: 
L173:         if (i != ri) Serial.println("failed: int");
L174:         if (f != rf) Serial.println("failed: float");
L175:         if (s != rs) Serial.println("failed: string");
L176:         if (v != rv) Serial.println("failed: vector<int>");
L177:         if (m != rm) Serial.println("failed: map<string, int>");
L178: 
L179:         Serial.println("msgpack test success");
L180:     }
L181: 
L182:     void loop() {}
L183: ###### Encode / Decode to Collections without Container
L184: In msgpack, there are two collection types: `Array` and `Map`. C++ containers will be converted to one of them but you can do that from individual parameters. To `pack` / `unpack` values as such collections in a simple way, please use these functions.
L185: 
L186:     packer.to_array(i, f, s); // becoms array format [i, f, s];
L187:     unpacker.from_array(ii, ff, ss); // unpack from array format to ii, ff, ss
L188: 
L189:     packer.to_map("i", i, "f", f); // becoms {"i":i, "f":f}
L190:     unpacker.from_map(ki, ii, kf, ff); // unpack from map to ii, ff, ss
L191: The same conversion can be achieved using `serialize` and `deserialize`.
L192: 
L193:     packer.serialize(MsgPack::arr_size_t(3), i, f, s); // [i, f, s]
L194:     unpacker.deserialize(MsgPack::arr_size_t(3), ii, ff, ss);
L195: 
L196:     packer.serialize(MsgPack::map_size_t(2), "i", i, "f", f); // {"i":i, "f":f}
L197:     unpacker.deserialize(MsgPack::map_size_t(2), ki, ii, kf, ff);
L198: Here, `MsgPack::arr_size_t` and `MsgPack::map_size_t` are used to identify the size of `Array` and `Map` format in `serialize` or `deserialize`. This way is expandable to `pack` and `unpack` complex data structure because it can be nested.
L199: 
L200:     // {"i":i, "arr":[ii, iii]}
L201:     packer.serialize(MsgPack::map_size_t(2), "i", i, "arr", MsgPack::arr_size_t(2), ii, iii);
L202:     unpacker.deserialize(MsgPack::map_size_t(2), ki, i, karr, MsgPack::arr_size_t(2), ii, iii);
L203: ###### Custom Class Adaptation
L204: 
L205: To serialize / deserialize custom type you defined, please use `MSGPACK_DEFINE()` macro inside of your class. This macro enables you to convert your custom class to `Array` format.
L206: 
L207:     struct CustomClass {
L208:         int i;
L209:         float f;
L210:         MsgPack::str_t s;
L211:         MSGPACK_DEFINE(i, f, s); // -> [i, f, s]
L212:     };
L213: After that, you can `serialize` your class completely same as other types.
L214: 
L215:     int i;
L216:     float f;
L217:     MsgPack::str_t s;
L218:     CustomClass c;
L219: 
L220:     MsgPack::Packer packer;
L221:     packer.serialize(i, f, s, c);
L222:     // -> packer.serialize(i, f, s, arr_size_t(3), c.i, c.f, c.s)
L223: 
L224:     int ii;
L225:     float ff;
L226:     MsgPack::str_t ss;
L227:     CustomClass cc;
L228: 
L229:     MsgPack::Unpacker unpacker;
L230:     unpacker.feed(packer.data(), packer.size());
L231:     unpacker.deserialize(ii, ff, ss, cc);
L232: You can also wrap your custom class to `Map` format by using `MSGPACK_DEFINE_MAP` macro. Please note that you need "key" string for `Map` format.
L233: 
L234:     struct CustomClass {
L235:         MsgPack::str_t key_i {"i"}; int i;
L236:         MsgPack::str_t key_f {"f"}; float f;
L237:         MSGPACK_DEFINE_MAP(key_i, i, key_f, f); // -> {"i":i, "f":f}
L238:     };
L239: 
L240:     CustomClass c;
L241:     MsgPack::Packer packer;
L242:     packer.serialize(c);
L243:     // -> packer.serialize(map_size_t(2), c.key_i, c.i, c.key_f, c.f)
L244: 
L245:     CustomClass cc;
L246:     MsgPack::Unpacker unpacker;
L247:     unpacker.feed(packer.data(), packer.size());
L248:     unpacker.deserialize(cc);
L249: Custom Class with Inheritance
L250: 
L251: Also you can use `MSGPACK_BASE()` macro to pack values of base class.
L252: 
L253:     struct Base {
L254:         int i;
L255:         float f;
L256:         MSGPACK_DEFINE(i, f);
L257:     };
L258: 
L259:     struct Derived : public Base {
L260:         MsgPack::str_t s;
L261:         MSGPACK_DEFINE(s, MSGPACK_BASE(Base));
L262:         // -> packer.serialize(arr_size_t(2), s, arr_size_t(2), Base::i, Base::f)
L263:     };
L264: If you wamt to use `Map` format in derived class, add "key" for your `MSGPACK_BASE`.
L265: 
L266:     struct Derived : public Base {
L267:         MsgPack::str_t key_s; MsgPack::str_t s;
L268:         MsgPack::str_t key_b; // key for base class
L269:         MSGPACK_DEFINE_MAP(key_s, s, key_b, MSGPACK_BASE(Base));
L270:         // -> packer.serialize(map_size_t(2), key_s, s, key_b, arr_size_t(2), Base::i, Base::f)
L271:     };
L272: 
L273: Nested Custom Class
L274: You can nest custom classes to express complex data structure.
L275: 
L276:     // serialize and deserialize nested structure
L277:     // {"i":i, "f":f, "a":["str", {"first":1, "second":"two"}]}
L278: 
L279:     // {"first":1, "second":"two"}
L280:     struct MyMap {
L281:         MsgPack::str_t key_first; int i;
L282:         MsgPack::str_t key_second; MsgPack::str_t s;
L283:         MSGPACK_DEFINE_MAP(key_first, i, key_second, s);
L284:     };
L285: 
L286:     // ["str", {"first":1, "second":"two"}]
L287:     struct MyArr {
L288:         MsgPack::str_t s;
L289:         MyMap m;
L290:         MSGPACK_DEFINE(s, m):
L291:     };
L292: 
L293:     // {"i":i, "f":f, "a":["str", {"first":1, "second":"two"}]}
L294:     struct MyNestedClass {
L295:         MsgPack::str_t key_i; int i;
L296:         MsgPack::str_t key_f; int f;
L297:         MsgPack::str_t key_a;
L298:         MyArr arr;
L299:         MSGPACK_DEFINE_MAP(key_i, i, key_f, f, key_a, arr);
L300:     };
L301: And you can `serialize` / `deserialize` as same as other types.
L302: 
L303:     MyNestedClass c;
L304:     MsgPack::Packer packer;
L305:     packer.serialize(c);
L306: 
L307:     MyNestedClass cc;
L308:     MsgPack::Unpacker unpacker;
L309:     unpacker.feed(packer.data(), packer.size());
L310:     unpacker.deserialize(cc);
L311: ###### JSON and Other language's msgpack compatibility
L312: In other languages like JavaScript, Python and etc. has also library for msgpack. But some libraries can NOT convert msgpack in "plain" style. They always wrap them into collections like `Array` or `Map` by default. For example, you can't convert "plain" format in other languages.
L313: 
L314:     packer.serialize(i, f, s);                // "plain" format is NOT unpackable
L315:     packer.serialize(arr_size_t(3), i, f, s); // unpackable if you wrap that into Array
L316: It is because the msgpack is used as based on JSON (I think). So you need to use `Array` format for JSON array, and `Map` for Json Object. To achieve that, there are several ways.
L317:   * use `to_array` or `to_map` to convert to simple structure
L318:   * use `serialize()` or `deserialize()` with `arr_size_t` / `map_size_t` for complex structure
L319:   * use custom class as JSON array / object which is wrapped into `Array` / `Map`
L320:   * use custom class nest recursively for more complex structure
L321:   * use `ArduinoJson` for more flexible handling of JSON
L322: Use MsgPack with ArduinoJson
L323:   * you can [serialize / deserialize] `StaticJsonDocument<N>` and `DynamicJsonDocument` directly
L324: 
L325:     #include <ArduinoJson.h>  // include before MsgPack.h
L326:     #include <MsgPack.h>
L327: 
L328:     void setup() {
L329:         StaticJsonDocument<200> doc_in;
L330:         MsgPack::Packer packer;
L331:         packer.serialize(doc_in); // serialize directly
L332: 
L333:         StaticJsonDocument<200> doc;
L334:         MsgPack::Unpacker unpacker;
L335:         unpacker.feed(packer.data(), packer.size());
L336:         unpacker.deserialize(doc); // deserialize directly
L337:     }

L461: 
L462: These types have type aliases like this:
L463:

L517: Packet Data Storage Class Inside
L518: STL is used to handle packet data by default, but for following boards/architectures, cite12†ArxContainer†github.com is used to store the packet data because STL can not be used for such boards. The storage size of such boards for max packet binary size and number of msgpack objects are limited.
L519: 
L520:   * AVR
L521:   * megaAVR
L522:   * SAMD
L523: Memory Management (for NO-STL Boards)
L524: As mentioned above, for such boards like Arduino Uno, the storage sizes are limited. And of course you can manage them by defining following macros. But these default values are optimized for such boards, please be careful not to excess your boards storage/memory.
L525: 
L526:     // msgpack serialized binary size
L527:     #define MSGPACK_MAX_PACKET_BYTE_SIZE  128
L528:     // max size of MsgPack::arr_t
L529:     #define MSGPACK_MAX_ARRAY_SIZE          8
L530:     // max size of MsgPack::map_t
L531:     #define MSGPACK_MAX_MAP_SIZE            8
L532:     // msgpack objects size in one packet
L533:     #define MSGPACK_MAX_OBJECT_SIZE        24
L534: These macros have no effect for STL enabled boards.
L535: 
L536: In addtion for such boards, type aliases for following types are different from others.
L537: 
L538:   * `MsgPack::str_t` = `String`
L539:   * `MsgPack::bin_t<T>` = `arx::vector<T, N = MSGPACK_MAX_PACKET_BYTE_SIZE>`
L540:   * `MsgPack::arr_t<T>` = `arx::vector<T, N = MSGPACK_MAX_ARRAY_SIZE>`
L541:   * `MsgPack::map_t<T, U>` = `arx::map<T, U, N = MSGPACK_MAX_MAP_SIZE>`
L542: 
L543: Please see "Memory Management" section and cite12†ArxContainer†github.com for detail.
L544: STL library for Arduino Support
L545: 
L546: For such boards, there are several STL libraries, like cite14†ArduinoSTL†github.com , cite15†StandardCPlusPlus†github.com , and so on. But such libraries are mainly based on cite16†uClibc++†cxx.uclibc.org and it has many lack of function. I considered to support them but I won't support them unless uClibc++ becomes much better compatibility to standard C++ library. I reccomend to use low cost but much better performance chip like ESP series.
