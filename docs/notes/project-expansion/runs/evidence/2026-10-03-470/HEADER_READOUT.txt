## Editorial notes on fixed upstream text

The original generated body below is retained. These notes identify discrepancies found by comparing the fixed 0.8.4 header, its implementation, and the scoped specification. They are editorial additions, not upstream corrections.

- **secret-seed-240-boundary**: For XXH3_64bits_withSecretandSeed and XXH3_128bits_withSecretandSeed, the fixed implementation uses the seed and default secret for lengths up to and including 240 bytes, and the supplied secret above 240 bytes. The original prose uses a different boundary. This observation comes from static implementation and specification comparison; numerical hash tests have not been run.
- **128-secret-seed-return**: XXH3_128bits_withSecretandSeed returns XXH128_hash_t according to its declaration and implementation. Its original Returns text lists XXH_OK/XXH_ERROR. Those error codes belong to reset operations, not this hash result.
- **128-seed-zero-family**: The seed-zero note under XXH3_128bits_withSeed points to XXH3_64bits(). The preceding XXH3_128bits documentation describes equivalence to XXH3_128bits_withSeed with zero seed. The fixed implementation also stays in the 128-bit family. Numerical equivalence has not been tested here.
- **argc-example**: The XXH3_generateSecret example uses argv != 3 in its argument-count condition. The variable names and types are inconsistent with an argument-count check. The original example is preserved; no compilation result is claimed.
- **hashfast-seed-example**: The HashFast constructor takes a parameter named s, but calls XXH3_generateSecret_fromSeed with seed, which is not declared in that class. The original example is preserved; no compiled correction or performance guarantee is supplied.
- **stale-state-field-reference**: Some state comments refer to XXH32_state_s::mem32 and ::memsize. The fixed XXH32 state fields are buffer and bufferedSize. These old reference names are preserved rather than treated as valid field links.
