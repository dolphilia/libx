1 [h1] Classes

2 [p] Every value in Wren is an object, and every object is an instance of a class.
Even ⟦CODE0⟧ and ⟦CODE1⟧ are full-featured objects—instances of the
<a href="/docs/wren/v0-4-0/en/02-reference/01-modules-core-bool/">Bool</a> class.

3 [p] Classes define an objects <em>behavior</em> and <em>state</em>. Behavior is defined by
<a href="/docs/wren/v0-4-0/en/01-guide/07-method-calls/"><em>methods</em></a> which live in the class. Every object of the same
class supports the same methods. State is defined in <em>fields</em>, whose values are
stored in each instance.

56 [h2] Fields <a class="header-anchor" href="#fields" name="fields">#</a>

57 [p] All state stored in instances is stored in <em>fields</em>. Each field has a name
that starts with an underscore.

58 [p] Here, ⟦CODE0⟧ and ⟦CODE1⟧ in the ⟦CODE2⟧ <a href="/docs/wren/v0-4-0/en/01-guide/10-classes/#methods">getter</a> refer
to fields on the rectangle instance. You can think of them like ⟦CODE3⟧
and ⟦CODE4⟧ in other languages.

59 [p] When a field name appears, Wren looks for the nearest enclosing class and looks
up the field on the instance of that class. Field names cannot be used outside
of an instance method. They <em>can</em> be used inside a <a href="/docs/wren/v0-4-0/en/01-guide/11-functions/">function</a>
in a method. Wren will look outside any nested functions until it finds an
enclosing method.

60 [p] Unlike <a href="/docs/wren/v0-4-0/en/01-guide/09-variables/">variables</a>, fields are implicitly declared by simply
assigning to them. If you access a field before it has been initialized, its
value is ⟦CODE0⟧.

77 [h2] Inheritance <a class="header-anchor" href="#inheritance" name="inheritance">#</a>

78 [p] A class can inherit from a “parent” or <em>superclass</em>. When you invoke a method
on an object of some class, if it can’t be found, it walks up the chain of
superclasses looking for it there.

79 [p] By default, any new class inherits from Object, which is the superclass from
which all other classes ultimately descend. You can specify a different parent
class using ⟦CODE0⟧ when you declare the class:

80 [p] This declares a new class Pegasus that inherits from Unicorn.

81 [p] Note that you should not create classes that inherit from the built-in types
(Bool, Num, String, Range, List). The built-in types expect their internal bit
representation to be very specific and get horribly confused when you invoke one
of the inherited built-in methods on the derived type.

82 [p] The metaclass hierarchy does <em>not</em> parallel the regular class hierarchy. So, if
Pegasus inherits from Unicorn, Pegasus’s metaclass does not inherit from
Unicorn’s metaclass. In more prosaic terms, this means that static methods are
not inherited.
