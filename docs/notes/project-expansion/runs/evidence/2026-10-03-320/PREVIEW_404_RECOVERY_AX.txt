				144 text Welcome to cJSON.
			145 text cJSON aims to be the dumbest possible parser that you can get your job done with. It's a single file of C, and a single header file. JSON is described best here: http://www.json.org/ It's like XML, but fat-free. You use it to move data around, store things, or just generally represent your program's state. As a library, cJSON exists to take away as much legwork as it can, but not get in your way. As a point of pragmatism (i.e. ignoring the truth), I'm going to say that you can use it in one of two modes: Auto and Manual. Let's have a quick run-through. I lifted some JSON from this page: http://www.json.org/fatfree.html That page inspired me to write cJSON, which is a parser that tries to share the same philosophy as JSON itself. Simple, dumb, out of the way.

				271 text Data Structure
			272 text cJSON represents JSON data using the 
			273 text cJSON
			274 text  struct data type:
			275 button Copy code
			276 text /* The cJSON structure: */
typedef struct cJSON
{
    struct cJSON *next;
    struct cJSON *prev;
    struct cJSON *child;
    int type;
    char *valuestring;
    /* writing to valueint is DEPRECATED, use cJSON_SetNumberValue instead */
    int valueint;
    double valuedouble;
    char *string;
} cJSON;

			277 text An item of this type represents a JSON value. The type is stored in 
			278 text type
			279 text  as a bit-flag (
			280 container
				281 text this means that you cannot find out the type by just comparing the value of  type
			282 text ). To check the type of an item, use the corresponding 
			283 text cJSON_Is...
			284 text  function. It does a 
			285 text NULL
			286 text  check followed by a type check and returns a boolean value if the item is of this type. The type can be one of the following:
			287 content list
				288 container

				291 container

				294 container
					295 AXListMarker •

				300 container

			337 text . Adding it to an array or object transfers its ownership so that when that array or object is deleted, it gets deleted as well. You also could use

			339 text  to change a

			361 heading Arrays, Value: 4, ID: arrays
				362 text Arrays
			363 text You can create an empty array with 
			364 text cJSON_CreateArray
			365 text . 
			366 text cJSON_CreateArrayReference
			367 text  can be used to create an array that doesn't "own" its content, so its content doesn't get deleted by 
			368 text cJSON_Delete
			369 text . To add items to an array, use 
			370 text cJSON_AddItemToArray
			371 text  to append items to the end. Using 
			372 text cJSON_AddItemReferenceToArray
			373 text  an element can be added as a reference to another item, array or string. This means that 
			374 text cJSON_Delete
			375 text  will not delete that items 
			376 text child
			377 text  or 
			378 text valuestring
			379 text  properties, so no double frees are occurring if they are already used elsewhere. To insert items in the middle, use 
			380 text cJSON_InsertItemInArray
			381 text . It will insert an item at the given 0 based index and shift all the existing items to the right. If you want to take an item out of an array at a given index and continue using it, use 
			382 text cJSON_DetachItemFromArray
			383 text , it will return the detached item, so be sure to assign it to a pointer, otherwise you will have a memory leak. Deleting items is done with 
			384 text cJSON_DeleteItemFromArray
			385 text . It works like 
			386 text cJSON_DetachItemFromArray
			387 text , but deletes the detached item via 
			388 text cJSON_Delete
			389 text . You can also replace an item in an array in place. Either with 
			390 text cJSON_ReplaceItemInArray
			391 text  using an index or with 
			392 text cJSON_ReplaceItemViaPointer
			393 text  given a pointer to an element. 
			394 text cJSON_ReplaceItemViaPointer
			395 text  will return 
			396 text 0
			397 text  if it fails. What this does internally is to detach the old item, delete it and insert the new item in its place. To get the size of an array, use 
			398 text cJSON_GetArraySize
			399 text . Use 
			400 text cJSON_GetArrayItem
			401 text  to get an element at a given index. Because an array is stored as a linked list, iterating it via index is inefficient (
			402 text O(n²)
			403 text ), so you can iterate over an array using the 
			404 text cJSON_ArrayForEach
			405 text  macro in 
			406 text O(n)
			407 text  time complexity.

			412 text . 
			413 text cJSON_CreateObjectReference
			414 text  can be used to create an object that doesn't "own" its content, so its content doesn't get deleted by 
			415 text cJSON_Delete
			416 text . To add items to an object, use 
			417 text cJSON_AddItemToObject
			418 text . Use 
			419 text cJSON_AddItemToObjectCS
			420 text  to add an item to an object with a name that is a constant or reference (key of the item, 
			421 text string
			422 text  in the 
			423 text cJSON
			424 text  struct), so that it doesn't get freed by 
			425 text cJSON_Delete
			426 text . Using 
			427 text cJSON_AddItemReferenceToArray
			428 text  an element can be added as a reference to another object, array or string. This means that 
			429 text cJSON_Delete
			430 text  will not delete that items 
			431 text child
			432 text  or 
			433 text valuestring
			434 text  properties, so no double frees are occurring if they are already used elsewhere. If you want to take an item out of an object, use 
			435 text cJSON_DetachItemFromObjectCaseSensitive
			436 text , it will return the detached item, so be sure to assign it to a pointer, otherwise you will have a memory leak. Deleting items is done with 
			437 text cJSON_DeleteItemFromObjectCaseSensitive
			438 text . It works like 
			439 text cJSON_DetachItemFromObjectCaseSensitive
			440 text  followed by 
			441 text cJSON_Delete
			442 text . You can also replace an item in an object in place. Either with 
			443 text cJSON_ReplaceItemInObjectCaseSensitive
			444 text  using a key or with 
			445 text cJSON_ReplaceItemViaPointer
			446 text  given a pointer to an element. 
			447 text cJSON_ReplaceItemViaPointer
			448 text  will return 
			449 text 0
			450 text  if it fails. What this does internally is to detach the old item, delete it and insert the new item in its place. To get the size of an object, you can use 
			451 text cJSON_GetArraySize
			452 text , this works because internally objects are stored as arrays. If you want to access an item in an object, use 
			453 text cJSON_GetObjectItemCaseSensitive
			454 text . To iterate over an object, you can use the 
			455 text cJSON_ArrayForEach
			456 text  macro the same way as for arrays. cJSON also provides convenient helper functions for quickly creating a new item and adding it to an object, like 
			457 text cJSON_AddNullToObject
			458 text . They return a pointer to the new item or 
			459 text NULL
			460 text  if they failed.

			468 text Given some JSON in a string (whether zero terminated or not), you can parse it with 
			469 text cJSON_ParseWithLength
			470 text .
			471 button Copy code
			472 text cJSON *json = cJSON_ParseWithLength(string, buffer_length);

			473 text It will parse the JSON and allocate a tree of 
			474 text cJSON
			475 text  items that represents it. Once it returns, you are fully responsible for deallocating it after use with 
			476 text cJSON_Delete
			477 text . The allocator used by 
			478 text cJSON_Parse
			479 text  is 
			480 text malloc
			481 text  and 
			482 text free
			483 text  by default but can be changed (globally) with 
			484 text cJSON_InitHooks
			485 text . If an error occurs a pointer to the position of the error in the input string can be accessed using 
			486 text cJSON_GetErrorPtr
			487 text . Note though that this can produce race conditions in multithreading scenarios, in that case it is better to use 
			488 text cJSON_ParseWithOpts
			489 text  with 
			490 text return_parse_end
			491 text . By default, characters in the input string that follow the parsed JSON will not be considered as an error. If you want more options, use 
			492 text cJSON_ParseWithOpts(const char *value, const char **return_parse_end, cJSON_bool require_null_terminated)
			493 text . 
			494 text return_parse_end
			495 text  returns a pointer to the end of the JSON in the input string or the position that an error occurs at (thereby replacing 
			496 text cJSON_GetErrorPtr
			497 text  in a thread safe way). 
			498 text require_null_terminated
			499 text , if set to 
			500 text 1
			501 text  will make it an error if the input string contains data after the JSON. If you want more options giving buffer length, use 
			502 text cJSON_ParseWithLengthOpts(const char *value, size_t buffer_length, const char **return_parse_end, cJSON_bool require_null_terminated)

			504 heading Printing JSON, Value: 3, ID: printing-json
				505 text Printing JSON
			506 text Given a tree of 
			507 text cJSON
			508 text  items, you can print them as a string using 
			509 text cJSON_Print
			510 text .
			511 button Copy code
			512 text char *string = cJSON_Print(json);

			513 text It will allocate a string and print a JSON representation of the tree into it. Once it returns, you are fully responsible for deallocating it after use with your allocator. (usually 
			514 text free
			515 text , depends on what has been set with 
			516 text cJSON_InitHooks
			517 text ).
			518 text cJSON_Print
			519 text  will print with whitespace for formatting. If you want to print without formatting, use 
			520 text cJSON_PrintUnformatted
			521 text . If you have a rough idea of how big your resulting string will be, you can use 
			522 text cJSON_PrintBuffered(const cJSON *item, int prebuffer, cJSON_bool fmt)
			523 text . 
			524 text fmt
			525 text  is a boolean to turn formatting with whitespace on and off. 
			526 text prebuffer
			527 text  specifies the first buffer size to use for printing. 
			528 text cJSON_Print
			529 text  currently uses 256 bytes for its first buffer size. Once printing runs out of space, a new buffer is allocated and the old gets copied over before printing is continued. These dynamic buffer allocations can be completely avoided by using 
			530 text cJSON_PrintPreallocated(cJSON *item, char *buffer, const int length, const cJSON_bool format)
			531 text . It takes a buffer to a pointer to print to and its length. If the length is reached, printing will fail and it returns 
			532 text 0
			533 text . In case of success, 
			534 text 1
			535 text  is returned. Note that you should provide 5 bytes more than is actually needed, because cJSON is not 100% accurate in estimating if the provided memory is enough.

			543 text Let's build the above JSON and print it to a string:
			544 button Copy code
			545 text //create a monitor with a list of supported resolutions
//NOTE: Returns a heap allocated string, you are required to free it after use.
char *create_monitor(void)
{
    const unsigned int resolution_numbers[3][2] = {
        {1280, 720},
        {1920, 1080},
        {3840, 2160}
    };
    char *string = NULL;
    cJSON *name = NULL;
    cJSON *resolutions = NULL;
    cJSON *resolution = NULL;
    cJSON *width = NULL;
    cJSON *height = NULL;
    size_t index = 0;

    cJSON *monitor = cJSON_CreateObject();
    if (monitor == NULL)
    {
        goto end;
    }

    name = cJSON_CreateString("Awesome 4K");
    if (name == NULL)
    {
        goto end;
    }
    /* after creation was successful, immediately add it to the monitor,
     * thereby transferring ownership of the pointer to it */
    cJSON_AddItemToObject(monitor, "name", name);

    resolutions = cJSON_CreateArray();
    if (resolutions == NULL)
    {
        goto end;
    }
    cJSON_AddItemToObject(monitor, "resolutions", resolutions);

    for (index = 0; index < (sizeof(resolution_numbers) / (2 * sizeof(int))); ++index)
    {
        resolution = cJSON_CreateObject();
        if (resolution == NULL)
        {
            goto end;
        }
        cJSON_AddItemToArray(resolutions, resolution);

        width = cJSON_CreateNumber(resolution_numbers[index][0]);
        if (width == NULL)
        {
            goto end;
        }
        cJSON_AddItemToObject(resolution, "width", width);

        height = cJSON_CreateNumber(resolution_numbers[index][1]);
        if (height == NULL)
        {
            goto end;
        }
        cJSON_AddItemToObject(resolution, "height", height);
    }

    string = cJSON_Print(monitor);
    if (string == NULL)
    {
        fprintf(stderr, "Failed to print monitor.\n");
    }

end:
    cJSON_Delete(monitor);
    return string;
}

			551 heading Parsing, Value: 4, ID: parsing
				552 text Parsing
			553 text In this example we will parse a JSON in the above format and check if the monitor supports a Full HD resolution while printing some diagnostic output:
			554 button Copy code
			555 text /* return 1 if the monitor supports full hd, 0 otherwise */
int supports_full_hd(const char * const monitor)
{
    const cJSON *resolution = NULL;
    const cJSON *resolutions = NULL;
    const cJSON *name = NULL;
    int status = 0;
    cJSON *monitor_json = cJSON_Parse(monitor);
    if (monitor_json == NULL)
    {
        const char *error_ptr = cJSON_GetErrorPtr();
        if (error_ptr != NULL)
        {
            fprintf(stderr, "Error before: %s\n", error_ptr);
        }
        status = 0;
        goto end;
    }

    name = cJSON_GetObjectItemCaseSensitive(monitor_json, "name");
    if (cJSON_IsString(name) && (name->valuestring != NULL))
    {
        printf("Checking monitor \"%s\"\n", name->valuestring);
    }

    resolutions = cJSON_GetObjectItemCaseSensitive(monitor_json, "resolutions");
    cJSON_ArrayForEach(resolution, resolutions)
    {
        cJSON *width = cJSON_GetObjectItemCaseSensitive(resolution, "width");
        cJSON *height = cJSON_GetObjectItemCaseSensitive(resolution, "height");

        if (!cJSON_IsNumber(width) || !cJSON_IsNumber(height))
        {
            status = 0;
            goto end;
        }

        if ((width->valuedouble == 1920) && (height->valuedouble == 1080))
        {
            status = 1;
            goto end;
        }
    }

end:
    cJSON_Delete(monitor_json);
    return status;
}
