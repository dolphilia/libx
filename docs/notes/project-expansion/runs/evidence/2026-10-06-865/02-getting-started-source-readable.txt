1 [h1] Getting Started

2 [h2] Trying out the language <a class="header-anchor" href="#trying-out-the-language" name="trying-out-the-language">#</a>

3 [p] If you’d like to try Wren, you have a few options.

4 [li] <strong>In your browser.</strong> You can try Wren <strong><a href="https://wren.io/try">right here</a></strong>!

5 [li] <strong>On your computer.</strong> The <a href="https://wren.io/cli">Wren CLI</a> project is a downloadable executable
      to run scripts with access to file io and more. See the <a href="https://wren.io/cli">Wren CLI docs</a>.

6 [li] <strong>Embedded in your code.</strong> See how to <a href="#embed-the-vm">build and embed Wren</a> below. <br/>
    And then read the <a href="/docs/wren/v0-4-0/en/01-guide/16-embedding/">embedding guide</a>!

7 [p] Once you have somewhere to explore, it’s time to <a href="/docs/wren/v0-4-0/en/01-guide/03-syntax/">learn the
language</a>.

8 [h2] Embed the VM <a class="header-anchor" href="#embed-the-vm" name="embed-the-vm">#</a>

9 [p] <strong>The Wren Virtual Machine</strong> is the core of the language that executes Wren
    source code. It is just a library, not a standalone application. It’s
    designed to be <a href="/docs/wren/v0-4-0/en/01-guide/16-embedding/">embedded</a> in a larger host application.

10 [p] It has no dependencies beyond the C standard library.
You can use it as a static library, shared library, or simply compile the source into your app.

11 [h3] Building Wren <a class="header-anchor" href="#building-wren" name="building-wren">#</a>

12 [p] To build the Wren library, we look inside the ⟦CODE0⟧ folder.
In here you’ll find ready to go projects for ⟦CODE1⟧, ⟦CODE2⟧ and tools like ⟦CODE3⟧.

13 [li] <strong>Windows</strong> Open ⟦CODE0⟧ inside ⟦CODE1⟧ (or ⟦CODE2⟧), hit build.

14 [li] <strong>Mac</strong> Open ⟦CODE0⟧ inside ⟦CODE1⟧, hit build.

15 [li] <strong>Linux</strong> Run ⟦CODE0⟧ inside of ⟦CODE1⟧.

16 [p] In each case, <strong>there will be library files generated into the root ⟦CODE0⟧ folder</strong>. <br/>
These are what you’ll link into your project, based on your needs.

17 [li] <strong>Static Linking</strong> ⟦CODE0⟧ on Windows, ⟦CODE1⟧ elsewhere.

18 [li] <strong>Dynamic Linking</strong> ⟦CODE0⟧ on Windows, ⟦CODE1⟧ on Linux, and ⟦CODE2⟧ on Mac.

19 [p] <small>
  Note that the default build will also generate ⟦CODE0⟧ inside of ⟦CODE1⟧, <br/>
  a binary that is used to run the language tests. It can execute simple scripts.
</small>

20 [p] <strong>Other platforms</strong> <br/>
If your platform isn’t explicitly supported,
it is recommended that you include the Wren source
in your project for a portable experience.

21 [h3] Including the code in your project <a class="header-anchor" href="#including-the-code-in-your-project" name="including-the-code-in-your-project">#</a>

22 [p] <strong>all source files</strong> <br/>
The alternative to building via the provided projects is to include the wren source code in your project.
Since it has no dependencies this is simple, all the code in ⟦CODE0⟧ comes along. There’s a readme in ⟦CODE1⟧ for details.

23 [p] <strong>‘amalgamated’ build</strong> <br/>
If you want an even simpler way, there’s an ‘amalgamated’ build (often called ⟦CODE0⟧, or ⟦CODE1⟧ builds.).
This is <em>all of the wren source code in one file</em>.

24 [p] This file can be generated by running ⟦CODE0⟧, 
which saves the generated output in ⟦CODE1⟧.

25 [p] Include ⟦CODE0⟧ and ⟦CODE1⟧ in your project code and you’re good to go.
<small>Ideally later we can automate generating this and include it in the repo.</small>
