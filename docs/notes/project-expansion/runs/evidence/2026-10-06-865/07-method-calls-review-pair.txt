1 [h1]
EN: Method Calls
JA: メソッド呼び出し

2 [p]
EN: Wren is deeply object oriented, so most code consists of invoking methods on
objects, usually something like this:
JA: Wrenは徹底したオブジェクト指向言語なので、多くのコードはオブジェクトのメソッドを呼び出すもので、通常は次のような形になります。

3 [p]
EN: You have a <em>receiver</em> expression (here ⟦CODE0⟧) followed by a ⟦CODE1⟧, then a name
(⟦CODE2⟧) and an argument list in parentheses (⟦CODE3⟧). Multiple arguments
are separated by commas:
JA: <em>レシーバー</em>となる式（ここでは⟦CODE0⟧）に続けて、⟦CODE1⟧、名前（⟦CODE2⟧）、丸括弧で囲んだ引数リスト（⟦CODE3⟧）を書きます。引数が複数ある場合は、コンマで区切ります。

4 [p]
EN: The argument list can also be empty:
JA: 引数リストは空でもかまいません。

5 [p]
EN: The VM executes a method call like so:
JA: VMは、次の手順でメソッド呼び出しを実行します。

6 [li]
EN: Evaluate the receiver and arguments from left to right.
JA: レシーバーと引数を左から右へ評価する。

7 [li]
EN: Look up the method on the receiver’s <a href="/docs/wren/v0-4-0/en/01-guide/10-classes/">class</a>.
JA: レシーバーの<a href="/docs/wren/v0-4-0/en/01-guide/10-classes/">クラス</a>でメソッドを探す。

8 [li]
EN: Invoke it, passing in the argument values.
JA: 引数の値を渡して、そのメソッドを呼び出す。

9 [h2]
EN: Signature <a class="header-anchor" href="#signature" name="signature">#</a>
JA: シグネチャ <a class="header-anchor" href="#signature" name="signature">#</a>

10 [p]
EN: Unlike most other dynamically-typed languages, in Wren a class can have multiple
methods with the same <em>name</em>, as long as they have different <em>signatures</em>. The
signature includes the method’s name along with the number of arguments it
takes. In technical terms, this means you can <em>overload by arity</em>.
JA: ほかの多くの動的型付け言語とは異なり、Wrenでは<em>シグネチャ</em>が違っていれば、同じ<em>名前</em>のメソッドを一つのクラスに複数定義できます。シグネチャには、メソッド名と受け取る引数の数が含まれます。専門的に言うと、<em>引数の個数によるオーバーロード</em>が可能です。

11 [p]
EN: For example, the <a href="/docs/wren/v0-4-0/en/02-reference/17-modules-random-random/">Random</a> class has two methods for getting a random integer.
One takes a minimum and maximum value and returns a value in that range. The
other only takes a maximum value and uses 0 as the minimum:
JA: 例えば、<a href="/docs/wren/v0-4-0/en/02-reference/17-modules-random-random/">Random</a>クラスには、乱数の整数を得るメソッドが二つあります。一方は最小値と最大値を受け取り、その範囲の値を返します。もう一方は最大値だけを受け取り、最小値に0を使います。

12 [p]
EN: In a language like Python or JavaScript, these would both call a single ⟦CODE0⟧
method, which has some kind of “optional” parameter. The body of the method
figures out how many arguments were passed and uses control flow to handle the
two different behaviors. That means first parameter represents “max unless
another parameter was passed, in which case it’s min”. 
JA: PythonやJavaScriptのような言語では、どちらも何らかの「省略可能な」パラメーターを持つ一つの⟦CODE0⟧メソッドを呼び出します。メソッドの本体で渡された引数の数を調べ、制御フローを使って二つの動作を処理します。つまり、最初のパラメーターは「別のパラメーターが渡されていなければmax、渡されていればmin」を表します。

13 [p]
EN: This type of ‘variadic’ code isn’t ideal, so Wren doesn’t encourage it.
JA: この種の「可変引数」のコードは理想的ではないため、Wrenでは推奨していません。

14 [p]
EN: In Wren, these are calls to two entirely separate methods, ⟦CODE0⟧ and
⟦CODE1⟧. This makes it easier to define “overloads” like this since you don’t
need optional parameters or any kind of control flow to handle the different
cases.
JA: Wrenでは、これらは⟦CODE0⟧と⟦CODE1⟧という、完全に別々の二つのメソッドへの呼び出しです。省略可能なパラメーターも、場合分けのための制御フローも必要ないので、このような「オーバーロード」を定義しやすくなります。

15 [p]
EN: It’s also faster to execute. Since we know how many arguments are passed at
compile time, we can compile this to directly call the right method and avoid
any “if I got two arguments do this…” runtime work.
JA: 実行も速くなります。渡す引数の数はコンパイル時に分かるため、適切なメソッドを直接呼び出すコードを生成でき、「引数が二つならこうする……」という実行時の処理を避けられます。

16 [h2]
EN: Getters <a class="header-anchor" href="#getters" name="getters">#</a>
JA: ゲッター <a class="header-anchor" href="#getters" name="getters">#</a>

17 [p]
EN: Some methods exist to expose a stored or computed property of an object. These
are <em>getters</em> and have no parentheses:
JA: オブジェクトが保存しているプロパティーや、計算して求めるプロパティーを公開するためのメソッドがあります。これらは<em>ゲッター</em>で、丸括弧を付けません。

18 [p]
EN: A getter is <em>not</em> the same as a method with an empty argument list. The ⟦CODE0⟧ is
part of the signature, so ⟦CODE1⟧ and ⟦CODE2⟧ have different signatures.
Unlike Ruby’s optional parentheses, Wren wants to make sure you call a getter
like a getter and a ⟦CODE3⟧ method like a ⟦CODE4⟧ method. These don’t work:
JA: ゲッターは、空の引数リストを持つメソッドと<em>同じではありません</em>。⟦CODE0⟧はシグネチャの一部なので、⟦CODE1⟧と⟦CODE2⟧はシグネチャが異なります。Rubyの省略可能な丸括弧とは違い、Wrenはゲッターをゲッターとして、⟦CODE3⟧メソッドを⟦CODE4⟧メソッドとして呼び出すことを求めます。次の呼び出しは使えません。

19 [p]
EN: If you’re defining some member that doesn’t need any parameters, you need to
decide if it should be a getter or a method with an empty ⟦CODE0⟧ parameter list.
The general guidelines are:
JA: パラメーターが不要なメンバーを定義する場合は、ゲッターにするか、空の⟦CODE0⟧パラメーターリストを持つメソッドにするかを決める必要があります。一般的な指針は次のとおりです。

20 [li]
EN: If it modifies the object or has some other side effect, make it a method:
JA: オブジェクトを変更するか、何らかの副作用があるなら、メソッドにする。

21 [li]
EN: If the method supports multiple arities, make the zero-parameter case a ⟦CODE0⟧
    method to be consistent with the other versions:
JA: メソッドが複数の引数個数に対応するなら、ほかの版と一貫するよう、引数がゼロの場合も⟦CODE0⟧メソッドにする。

22 [li]
EN: Otherwise, it can probably be a getter.
JA: それ以外なら、おそらくゲッターにできます。

23 [h2]
EN: Setters <a class="header-anchor" href="#setters" name="setters">#</a>
JA: セッター <a class="header-anchor" href="#setters" name="setters">#</a>

24 [p]
EN: A getter lets an object expose a public “property” that you can <em>read</em>.
Likewise, a <em>setter</em> lets you write to a property:
JA: ゲッターは、<em>読み取れる</em>公開「プロパティー」をオブジェクトに持たせます。同様に、<em>セッター</em>はプロパティーへの書き込みを可能にします。

25 [p]
EN: Despite the ⟦CODE0⟧, this is just another syntax for a method call. From the
language’s perspective, the above line is just a call to the ⟦CODE1⟧
method on ⟦CODE2⟧, passing in ⟦CODE3⟧.
JA: ⟦CODE0⟧があっても、これはメソッド呼び出しの別の書き方にすぎません。言語の立場から見ると、上の行は単に⟦CODE2⟧の⟦CODE1⟧メソッドに⟦CODE3⟧を渡して呼び出しています。

26 [p]
EN: Since the ⟦CODE0⟧ is in the setter’s signature, an object can have both a getter
and setter with the same name without a collision. Defining both lets you
provide a read/write property.
JA: ⟦CODE0⟧はセッターのシグネチャに含まれるため、オブジェクトに同じ名前のゲッターとセッターを定義しても衝突しません。両方を定義すると、読み書きできるプロパティーを提供できます。

27 [h2]
EN: Operators <a class="header-anchor" href="#operators" name="operators">#</a>
JA: 演算子 <a class="header-anchor" href="#operators" name="operators">#</a>

28 [p]
EN: Wren has most of the same operators you know and love with the same precedence
and associativity. We have three prefix operators:
JA: Wrenには、なじみのある演算子の大半が、同じ優先順位と結合性で備わっています。前置演算子は三つあります。

29 [p]
EN: They are just method calls on their operand without any other arguments. An
expression like ⟦CODE0⟧ means “call the ⟦CODE1⟧ method on ⟦CODE2⟧”.
JA: これらは、ほかの引数を渡さずにオペランドのメソッドを呼び出すだけです。⟦CODE0⟧のような式は、「⟦CODE2⟧の⟦CODE1⟧メソッドを呼び出す」という意味です。

30 [p]
EN: We also have a slew of infix operators—they have operands on both sides.
They are:
JA: 両側にオペランドを持つ、中置演算子も多数あります。次のとおりです。

31 [p]
EN: Like prefix operators, they are all funny ways of writing method calls. The left
operand is the receiver, and the right operand gets passed to it. So ⟦CODE0⟧ is
semantically interpreted as “invoke the ⟦CODE1⟧ method on ⟦CODE2⟧, passing it ⟦CODE3⟧”.
JA: 前置演算子と同様、これらもすべて、メソッド呼び出しの変わった書き方です。左のオペランドがレシーバーで、右のオペランドを引数として渡します。したがって、⟦CODE0⟧は意味上、「⟦CODE2⟧の⟦CODE1⟧メソッドに⟦CODE3⟧を渡して呼び出す」と解釈します。

32 [p]
EN: Note that ⟦CODE0⟧ is both a prefix and an infix operator. Since they have different
signatures (⟦CODE1⟧ and ⟦CODE2⟧), there’s no ambiguity between them.
JA: ⟦CODE0⟧には前置演算子と中置演算子の両方がある点に注意してください。シグネチャが⟦CODE1⟧と⟦CODE2⟧で異なるので、両者に曖昧さはありません。

33 [p]
EN: Most of these are probably familiar already. The ⟦CODE0⟧ and ⟦CODE1⟧ operators are
“range” operators. The number type implements those to create <a href="/docs/wren/v0-4-0/en/01-guide/04-values/#ranges">range</a>
objects, but they are method calls like other operators.
JA: これらの大半は、すでになじみがあるでしょう。⟦CODE0⟧と⟦CODE1⟧は「範囲」演算子です。数値型は、<a href="/docs/wren/v0-4-0/en/01-guide/04-values/#ranges">範囲</a>オブジェクトを作成するためにこれらを実装していますが、ほかの演算子と同じように、メソッド呼び出しです。

34 [p]
EN: The ⟦CODE0⟧ keyword is a “type test” operator. The base <a href="/docs/wren/v0-4-0/en/02-reference/09-modules-core-object/">Object</a> class implements
it to tell if an object is an instance of a given class. You’ll rarely need to,
but you can override ⟦CODE1⟧ in your own classes. That can be useful for things
like mocks or proxies where you want an object to masquerade as a certain class.
JA: ⟦CODE0⟧キーワードは「型の検査」の演算子です。基底の<a href="/docs/wren/v0-4-0/en/02-reference/09-modules-core-object/">Object</a>クラスがこれを実装し、オブジェクトが指定したクラスのインスタンスかどうかを調べます。必要になることはまれですが、自分のクラスで⟦CODE1⟧をオーバーライドすることもできます。これは、特定のクラスに見せかけたいモックやプロキシーなどに役立ちます。
