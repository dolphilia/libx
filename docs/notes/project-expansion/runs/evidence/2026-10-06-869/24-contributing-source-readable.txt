1 [h1] Contributing

2 [p] Like the bird, Wren’s ecosystem is small but full of life. Almost everything is
under active development and there’s lots to do. We’d be delighted to have you
help.

3 [p] The first thing to do is to join <a href="https://discord.gg/Kx6PxSX">the discord community</a> (or <a href="https://groups.google.com/forum/#!forum/wren-lang">the mailing list</a>) and say,
“Hi”. There are no strangers to Wren, just friends we haven’t met yet.

4 [h2] Growing the ecosystem <a class="header-anchor" href="#growing-the-ecosystem" name="growing-the-ecosystem">#</a>

5 [p] The simplest and often most helpful way to join the Wren party is to be a Wren
<em>user</em>. Create an application that embeds Wren. Write a library or a handy
utility in Wren. Add syntax highlighting support for Wren to your favorite text
editor. Share that stuff and it will help the next Wren user to come along.

6 [p] If you do any of the above, let us know by adding it to <a href="https://github.com/wren-lang/wren/wiki">the wiki</a>. <br/>
We like to keep track of:

7 [li] <a href="https://github.com/wren-lang/wren/wiki/Applications">Applications</a> that host Wren as a scripting language.

8 [li] <a href="https://github.com/wren-lang/wren/wiki/Modules">Modules</a> written in Wren that others can use.

9 [li] <a href="https://github.com/wren-lang/wren/wiki/Language-Bindings">Language bindings</a> that let you interact with Wren from other
  languages.

10 [li] <a href="https://github.com/wren-lang/wren/wiki/Tools">Tools and utilities</a> that make it easier to be a Wren programmer.

11 [h2] Contributing to Wren <a class="header-anchor" href="#contributing-to-wren" name="contributing-to-wren">#</a>

12 [p] You’re also more than welcome to contribute to Wren itself, both the core VM and
the command-line interpreter. The source is developed <a href="https://github.com/wren-lang/">on GitHub</a>. Our
hope is that the codebase, tests, and <a href="https://github.com/wren-lang/wren/tree/main/doc/site">documentation</a> are easy to
understand and contribute to. If they aren’t, that’s a bug.

13 [p] You can learn how to build wren on the <a href="/docs/wren/v0-4-0/en/01-guide/02-getting-started/#building-wren">getting started page</a>.

14 [h3] Finding something to hack on <a class="header-anchor" href="#finding-something-to-hack-on" name="finding-something-to-hack-on">#</a>

15 [p] Between the <a href="https://github.com/wren-lang/wren/issues">issue tracker</a> and searching for ⟦CODE0⟧ comments in the
code, it’s pretty easy to find something that needs doing, though we don’t
always do a good job of writing everything down.

16 [p] If nothing there suits your fancy, new ideas are welcome as well! If you have an
idea for a significant change or addition, please file a <a href="https://github.com/wren-lang/wren/labels/proposal">proposal</a> to discuss
it before writing lots of code. Wren tries very <em>very</em> hard to be minimal which
means often having to say “no” to language additions, even really cool ones.

   you’re starting from a happy place before you poke at the code. Running the
   tests is as simple as <a href="/docs/wren/v0-4-0/en/01-guide/02-getting-started/#building-wren">building the vm project</a>,
   which generates ⟦CODE1⟧ and then running the following python 3 script:</p>
⟦PRE0⟧
<p>If there are no failures, you’re good to go.</p>


24 [li] 
<p><strong><a href="https://help.github.com/articles/fork-a-repo/">Fork the repo</a> so you can change it locally.</strong> Please make your
   changes in separate <a href="https://www.atlassian.com/git/tutorials/comparing-workflows/centralized-workflow">feature branches</a> to make things a little easier.</p>


25 [li] 
<p><strong>Change the code.</strong> Please follow the style of the surrounding code. That
   basically means ⟦CODE0⟧ names, ⟦CODE1⟧ on the next line, keep within 80
   columns, and two spaces of indentation. If you see places where the existing
   code is inconsistent, let us know.</p>


26 [li] 
<p><strong>Write some tests for your new functionality.</strong> They live under ⟦CODE0⟧.
   Take a look at some existing tests to get an idea of how to define
   expectations.</p>


27 [li] 
<p><strong>Make sure the tests all pass, both the old ones and your new ones.</strong></p>


28 [li] 
<p><strong>Add your name and email to the <a href="https://github.com/wren-lang/wren/tree/main/AUTHORS">AUTHORS</a> file if you haven’t already.</strong></p>


29 [li] 
<p><strong>Send a <a href="https://github.com/wren-lang/wren/pulls">pull request</a>.</strong> Pat yourself on the back for contributing to a
   fun open source project! </p>


30 [h2] Getting help <a class="header-anchor" href="#getting-help" name="getting-help">#</a>

on the <a href="https://discord.gg/Kx6PxSX">discord community</a> (or the <a href="https://groups.google.com/forum/#!forum/wren-lang">mailing list</a>). If you’re a Redditor, try the
<a href="https://www.reddit.com/r/wren_lang/">/r/wren_lang</a> subreddit. You can also email me directly (⟦CODE0⟧ at
