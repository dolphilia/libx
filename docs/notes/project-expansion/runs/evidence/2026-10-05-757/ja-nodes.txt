 — プロセスハンドル
プロセスハンドルは、新しいプロセスを起動します。ユーザーはそのプロセスを制御し、ストリームを使って通信経路を確立できます。

API
void
uv_disable_stdio_inheritance
(
void
)
このプロセスが親から継承したファイルディスクリプターとハンドルの継承を無効にします。これにより、このプロセスが起動する子プロセスに、これらのハンドルを誤って継承させることを防ぎます。
継承したファイルディスクリプターを閉じたり複製したりする前に、プログラムのできるだけ早い段階でこの関数を呼び出すことを推奨します。
注記
この関数は可能な範囲で動作します。libuvが継承されたすべてのファイルディスクリプターを発見できる保証はありません。一般に、UnixよりWindowsでよりよく機能します。

プロセスハンドルを初期化し、プロセスを開始します。起動に成功すると0を返します。失敗すると、起動できなかった理由に対応する負のエラーコードを返します。他のlibuvの初期化関数とは異なり、成功・失敗のいずれの場合も、最終的に次の関数を呼び出す必要があります: 
。ハンドルのメモリーを解放する前に、この関数でハンドルを閉じてください。
起動に失敗する理由には、実行するファイルが存在しない、指定したsetuidやsetgidを使う権限がない、新しいプロセスのためのメモリーを確保できない、などがあります。理由はこれらに限りません。
警告
Unixでは、プロセスがまだ終了していない時点で次の関数を呼び出すと、
uv_close
、libuvが回収できないゾンビプロセスを作ってしまいます。ユーザーが後で次の関数を呼び出す責任を負います: 
waitpid
。Windowsには関係ありません。
