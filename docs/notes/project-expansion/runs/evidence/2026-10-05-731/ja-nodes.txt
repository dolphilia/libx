 — 基底ハンドル
uv_handle_t
は、libuvのすべてのハンドル型の基底型です。
構造体は、libuvのどのハンドルも、
uv_handle_t
にキャストできるように配置されています。ここで定義するすべてのAPI関数は、どのハンドル型でも使えます。
libuvのハンドルは移動できません。関数に渡したハンドル構造体へのポインターは、要求した操作が続く間、有効でなければなりません。スタック上に確保したハンドルを使うときは注意してください。

int
uv_is_active
(
const
uv_handle_t
*

)
ハンドルがアクティブなら0以外、非アクティブなら0を返します。「アクティブ」の意味は、ハンドルの型によって異なります。
uv_async_tハンドルは常にアクティブです。uv_close()で閉じる場合を除き、非アクティブにできません。
uv_pipe_t、uv_tcp_t、uv_udp_tなど、基本的にI/Oを扱うハンドルは、読み取り、書き込み、接続、新しい接続の受け付けなど、I/Oに関係する処理を行っているときにアクティブです。
uv_check_t、uv_idle_t、uv_timer_tなどのハンドルは、uv_check_start()、uv_idle_start()などの呼び出しで開始したときにアクティブになります。
目安として、
uv_foo_t
型のハンドルに、
uv_foo_start()
関数がある場合は、その関数を呼び出した時点からアクティブです。同様に、
uv_foo_stop()
は、ハンドルを再び非アクティブにします。

ハンドルを閉じるよう要求します。
close_cb
は、この呼び出しの後で非同期に呼び出されます。メモリーを解放する前に、各ハンドルに対して必ずこの関数を呼び出してください。さらに、メモリーを解放できるのは、

ファイルディスクリプターを包むハンドルは即座に閉じられますが、

uv_connect_tやuv_write_tなどの進行中のリクエストはキャンセルされ、status=UV_ECANCELEDとして非同期にコールバックが呼び出されます。
close_cb
は、後処理やメモリーの解放が不要な場合、
NULL
