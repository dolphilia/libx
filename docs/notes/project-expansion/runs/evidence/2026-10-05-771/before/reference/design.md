<article class="libuv-document" id="furo-main-content" role="main">&#10;<section id="design-overview">&#10;<span id="design"></span><h1>設計概要<a class="headerlink" href="#design-overview" title="この見出しへの固定リンク">¶</a></h1>&#10;<p>libuvは、もともと、<a class="reference external" href="https://nodejs.org">Node.js</a>のために書かれた、クロスプラットフォームの支援ライブラリです。イベント駆動の非同期I/Oモデルを中心に設計されています。</p>&#10;<p>このライブラリは、異なるI/Oポーリング機構を単純に抽象化する以上の機能を提供します。「ハンドル」と「ストリーム」は、ソケットなどを扱う高水準の抽象化を提供します。また、クロスプラットフォームのファイルI/Oやスレッド機能なども提供します。</p>&#10;<p>次の図は、libuvを構成する各部分と、それらが関係するサブシステムを示しています。</p>&#10;<a class="reference internal image-reference" href="/docs/libuv/assets/v1-53-0/architecture.png"><img alt="Picture of libuv architecture" class="align-center" src="/docs/libuv/assets/v1-53-0/architecture.png" style="width: 765.0px; height: 369.75px;"/></a>&#10;<section id="handles-and-requests">&#10;<h2>ハンドルとリクエスト<a class="headerlink" href="#handles-and-requests" title="この見出しへの固定リンク">¶</a></h2>&#10;<p>libuvは、イベントループと組み合わせて使う、ハンドルとリクエストという2つの抽象化を提供します。</p>&#10;<p>ハンドルは、アクティブな間に特定の操作を行える、長く存続するオブジェクトを表します。例を挙げます。</p>&#10;<ul class="simple">&#10;<li><p>prepareハンドルは、アクティブな間、ループの反復ごとに1回コールバックが呼び出されます。</p></li>&#10;<li><p>TCPサーバーのハンドルは、新しい接続が発生するたびに接続コールバックが呼び出されます。</p></li>&#10;</ul>&#10;<p>リクエストは、通常は短時間で終わる操作を表します。ハンドルに対する操作もあり、writeリクエストはハンドルへデータを書き込むために使います。独立した操作もあり、getaddrinfoリクエストはハンドルを必要とせず、ループ上で直接実行されます。</p>&#10;<p>ハンドルとリクエストを扱う際の指針は次のとおりです。</p>&#10;<ol class="arabic simple">&#10;<li><p>ハンドルの初期化で、<cite>uv&#95;foo&#95;init()</cite>が成功した場合は、必ず、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/handle/#c.uv&#95;close" title="uv&#95;close"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;close()</span></code></a>を呼び出してください。ハンドルの初期化関数がエラーになった場合は、何もする必要はありません。</p></li>&#10;<li><p>閉じるのはハンドルだけで、リクエストは閉じません。たとえば、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/tcp/#c.uv&#95;tcp&#95;t" title="uv&#95;tcp&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;tcp&#95;t</span></code></a>はハンドルで、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/stream/#c.uv&#95;write&#95;t" title="uv&#95;write&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;write&#95;t</span></code></a>はリクエストです。</p></li>&#10;<li><p>ハンドルのメモリーを解放または再利用できるのは、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/handle/#c.uv&#95;close&#95;cb" title="uv&#95;close&#95;cb"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;close&#95;cb</span></code></a>の中、またはその後だけです。それより前にはできません。</p></li>&#10;<li><p>多くのハンドルには、初期化と開始・停止の関数がありますが、ないものもあります。たとえば、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/tcp/#c.uv&#95;tcp&#95;t" title="uv&#95;tcp&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;tcp&#95;t</span></code></a>と、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/process/#c.uv&#95;process&#95;t" title="uv&#95;process&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;process&#95;t</span></code></a>では異なります。<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/process/#c.uv&#95;spawn" title="uv&#95;spawn"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;spawn()</span></code></a>は、ハンドルの初期化とプロセスの開始を1つにまとめています。</p></li>&#10;<li><p>リクエストは、完了時、または、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/request/#c.uv&#95;cancel" title="uv&#95;cancel"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;cancel()</span></code></a>でキャンセルされたときに、自動的に閉じられます。</p></li>&#10;<li><p>追加の後処理が必要なのは、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/fs/#c.uv&#95;fs&#95;t" title="uv&#95;fs&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;fs&#95;t</span></code></a>と、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/dns/#c.uv&#95;getaddrinfo&#95;t" title="uv&#95;getaddrinfo&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;getaddrinfo&#95;t</span></code></a>のリクエストだけです。<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/fs/#c.uv&#95;fs&#95;t" title="uv&#95;fs&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;fs&#95;t</span></code></a>の場合は、使い終わったら、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/fs/#c.uv&#95;fs&#95;req&#95;cleanup" title="uv&#95;fs&#95;req&#95;cleanup"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;fs&#95;req&#95;cleanup()</span></code></a>を呼び出してください。<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/dns/#c.uv&#95;getaddrinfo&#95;t" title="uv&#95;getaddrinfo&#95;t"><code class="xref c c-type docutils literal notranslate"><span class="pre">uv&#95;getaddrinfo&#95;t</span></code></a>の場合は、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/dns/#c.uv&#95;freeaddrinfo" title="uv&#95;freeaddrinfo"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;freeaddrinfo()</span></code></a>です。</p></li>&#10;<li><p>リクエストのメモリーを解放または再利用できるのは、その時点以降だけです。</p></li>&#10;</ol>&#10;</section>&#10;<section id="the-i-o-loop">&#10;<h2>I/Oループ<a class="headerlink" href="#the-i-o-loop" title="この見出しへの固定リンク">¶</a></h2>&#10;<p>I/Oループ、つまりイベントループは、libuvの中心となる部分です。すべてのI/O操作の場を提供し、1つのスレッドに結び付けて使うことを意図しています。各ループを別々のスレッドで実行すれば、複数のイベントループを実行できます。libuvのイベントループや、ループ・ハンドルを扱う他のAPIも、特記がない限り、<strong>スレッドセーフではありません</strong>。</p>&#10;<p>イベントループは、一般的な、単一スレッドによる非同期I/Oの方式に従います。すべてのネットワークI/Oは非ブロッキングソケット上で行い、プラットフォームで利用できる最適な機構でポーリングします。Linuxではepoll、OSXや他のBSDではkqueue、SunOSではevent ports、WindowsではIOCPです。ループの反復の中で、ポーラーに追加したソケットのI/O活動を待つためにブロックし、ソケットの状態（読み取り可能、書き込み可能、切断）を示すコールバックを呼び出します。これにより、ハンドルは読み取り、書き込み、その他の必要なI/O操作を行えます。</p>&#10;<p>イベントループの動作を理解しやすくするため、次の図で、ループの1回の反復の全段階を示します。</p>&#10;<a class="reference internal image-reference" href="/docs/libuv/assets/v1-53-0/loop&#95;iteration.png"><img alt="Picture of libuv loop iteration" class="align-center" src="/docs/libuv/assets/v1-53-0/loop&#95;iteration.png" style="width: 343.5px; height: 642.0px;"/></a>&#10;<ol class="arabic">&#10;<li><p>ループが認識する「現在時刻」を最初に設定します。</p></li>&#10;<li><p>ループを、<code class="docutils literal notranslate"><span class="pre">UV&#95;RUN&#95;DEFAULT</span></code>で実行した場合は、期限に達したタイマーを実行します。ループが認識する、<em>現在時刻</em>より前に実行を予定した、アクティブなすべてのタイマーのコールバックを呼び出します。</p></li>&#10;<li><p>ループが、<em>存続中</em>なら反復を開始し、そうでなければ、すぐに終了します。では、ループはいつ、<em>存続中</em>とみなされるのでしょうか。アクティブで参照されているハンドル、アクティブなリクエスト、または閉じる処理中のハンドルがある場合は、<em>存続中</em>とみなされます。</p></li>&#10;<li><p>保留中のコールバックを呼び出します。通常、I/OコールバックはI/Oのポーリング直後に呼び出されます。ただし、次のループの反復へ延期される場合もあります。前の反復で延期したI/Oコールバックがあれば、この時点で実行します。</p></li>&#10;<li><p>idleハンドルのコールバックを呼び出します。名前は紛らわしいですが、アクティブなidleハンドルは、ループの反復ごとに実行されます。</p></li>&#10;<li><p>prepareハンドルのコールバックを呼び出します。prepareハンドルは、ループがI/Oでブロックする直前にコールバックが呼び出されます。</p></li>&#10;<li><p>ポーリングのタイムアウトを計算します。I/Oでブロックする前に、どれだけの時間ブロックするかを計算します。タイムアウトの計算規則は次のとおりです。</p>&#10;<blockquote>&#10;<div><ul class="simple">&#10;<li><p>ループを、<code class="docutils literal notranslate"><span class="pre">UV&#95;RUN&#95;NOWAIT</span></code>フラグで実行した場合、タイムアウトは0です。</p></li>&#10;<li><p>ループが停止しようとしている場合、つまり、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/loop/#c.uv&#95;stop" title="uv&#95;stop"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;stop()</span></code></a>が呼び出された場合、タイムアウトは0です。</p></li>&#10;<li><p>アクティブなハンドルもリクエストもない場合、タイムアウトは0です。</p></li>&#10;<li><p>アクティブなidleハンドルがある場合、タイムアウトは0です。</p></li>&#10;<li><p>閉じる処理を待つハンドルがある場合、タイムアウトは0です。</p></li>&#10;<li><p>以上のどれにも該当しない場合は、最も近いタイマーまでの時間を使います。アクティブなタイマーがなければ、無限に待ちます。</p></li>&#10;</ul>&#10;</div></blockquote>&#10;</li>&#10;<li><p>ループがI/Oでブロックします。この時点では、前の段階で計算した時間だけI/Oでブロックします。特定のファイルディスクリプターの読み取りや書き込みを監視していた、I/O関連のすべてのハンドルのコールバックを、この時点で呼び出します。</p></li>&#10;<li><p>checkハンドルのコールバックを呼び出します。checkハンドルは、ループがI/Oでブロックした直後にコールバックが呼び出されます。checkハンドルは、基本的にprepareハンドルに対応するものです。</p></li>&#10;<li><p>closeコールバックを呼び出します。<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/handle/#c.uv&#95;close" title="uv&#95;close"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;close()</span></code></a>を呼び出してハンドルを閉じた場合、closeコールバックが呼び出されます。</p></li>&#10;<li><p>ループが認識する「現在時刻」を更新します。</p></li>&#10;<li><p>期限に達したタイマーを実行します。「現在時刻」は、次のループの反復まで再び更新されないことに注意してください。そのため、他のタイマーを処理している間に期限に達したタイマーは、次のイベントループの反復まで実行されません。</p></li>&#10;<li><p>反復を終了します。ループを、<code class="docutils literal notranslate"><span class="pre">UV&#95;RUN&#95;NOWAIT</span></code>または、<code class="docutils literal notranslate"><span class="pre">UV&#95;RUN&#95;ONCE</span></code>のモードで実行した場合、反復が終了し、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/loop/#c.uv&#95;run" title="uv&#95;run"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;run()</span></code></a>が戻ります。<code class="docutils literal notranslate"><span class="pre">UV&#95;RUN&#95;DEFAULT</span></code>で実行した場合は、まだ、<em>存続中</em>なら先頭から続行し、そうでなければ終了します。</p></li>&#10;</ol>&#10;<div class="admonition important">&#10;<p class="admonition-title">重要</p>&#10;<p>libuvは、非同期のファイルI/O操作を実現するためにスレッドプールを使いますが、ネットワークI/Oは、<strong>常に</strong>各ループのスレッドという1つのスレッドで実行します。</p>&#10;</div>&#10;<div class="admonition note">&#10;<p class="admonition-title">注記</p>&#10;<p>ポーリングの機構は異なりますが、libuvはUnix系システムとWindowsの間で、一貫した実行モデルを提供します。</p>&#10;</div>&#10;</section>&#10;<section id="file-i-o">&#10;<h2>ファイルI/O<a class="headerlink" href="#file-i-o" title="この見出しへの固定リンク">¶</a></h2>&#10;<p>ネットワークI/Oと違い、libuvが利用できる、プラットフォーム固有のファイルI/Oプリミティブはありません。そのため、現在はスレッドプールでブロッキングのファイルI/O操作を実行しています。</p>&#10;<p>クロスプラットフォームのファイルI/Oの状況について詳しく知るには、<a class="reference external" href="https://blog.libtorrent.org/2012/10/asynchronous-disk-io/">この記事</a>を参照してください。</p>&#10;<p>libuvは現在、すべてのループが作業をキューに入れられる、グローバルなスレッドプールを使っています。このプールでは、現在、次の3種類の操作を実行します。</p>&#10;<blockquote>&#10;<div><ul class="simple">&#10;<li><p>ファイルシステム操作</p></li>&#10;<li><p>DNS関数（getaddrinfoとgetnameinfo）</p></li>&#10;<li><p>次を通じたユーザー指定のコード: <a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/threadpool/#c.uv&#95;queue&#95;work" title="uv&#95;queue&#95;work"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;queue&#95;work()</span></code></a></p></li>&#10;</ul>&#10;</div></blockquote>&#10;<div class="admonition warning">&#10;<p class="admonition-title">警告</p>&#10;<p>詳しくは、<a class="reference internal" href="/docs/libuv/v1-53-0/en/reference/threadpool/#threadpool"><span class="std std-ref">スレッドプールでの作業のスケジューリング</span></a>の節を参照してください。ただし、スレッドプールのサイズはかなり限られていることに注意してください。</p>&#10;</div>&#10;</section>&#10;</section>&#10;</article>
