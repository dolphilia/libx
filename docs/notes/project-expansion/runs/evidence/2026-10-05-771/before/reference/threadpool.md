&#10;<article class="libuv-document" id="furo-main-content" role="main">&#10;<section id="thread-pool-work-scheduling">&#10;<span id="threadpool"></span><h1>スレッドプールの作業スケジューリング<a class="headerlink" href="#thread-pool-work-scheduling" title="この見出しへの固定リンク">¶</a></h1>&#10;<p>libuvは、利用者のコードを実行し、イベントループのスレッドで通知を受け取るために使えるスレッドプールを提供します。内部では、このスレッドプールを使って、すべてのファイルシステム操作と、getaddrinfoおよびgetnameinfoのリクエストを実行します。</p>&#10;<p>既定のサイズは4ですが、起動時に環境変数<code class="docutils literal notranslate"><span class="pre">UV&#95;THREADPOOL&#95;SIZE</span></code>を任意の値に設定することで変更できます（絶対的な上限は1024です）。</p>&#10;<div class="versionchanged">&#10;<p><span changed">バージョン1.45.0で変更: </span>スレッドのスタックは、プラットフォームの既定値（小さすぎる場合があります）ではなく、8 MBになりました。</p>&#10;</div>&#10;<div class="versionchanged">&#10;<p><span class="versionmodified changed">バージョン1.50.0で変更: title="uv&#95;queue&#95;work"><code class="xref c c-func docutils literal notranslate"><span class="pre">uv&#95;queue&#95;work()</span></code></a>を使う場合など）、libuvは<code class="docutils literal notranslate"><span class="pre">UV&#95;THREADPOOL&#95;SIZE</span></code>で許可された最大数のスレッドを事前に割り当て、初期化します。通常、スレッドを増やすとスループットも上がりますが、メモリ使用量も増えます。ただし、ほとんどのプラットフォームでは、スレッドのスタックは必要になったときに拡張されます。</p>&#10;<div
