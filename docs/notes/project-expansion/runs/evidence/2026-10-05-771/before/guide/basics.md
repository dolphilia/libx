<article class="libuv-document" id="furo-main-content" role="main">&#10;<section id="basics-of-libuv">&#10;<h1>libuvの基礎<a class="headerlink" href="#basics-of-libuv" title="この見出しへの固定リンク">¶</a></h1>&#10;<p>libuvは、<strong>非同期</strong>、<strong>イベント駆動</strong>のプログラミング方式を要求します。中心となる役割は、イベントループと、コールバックによる入出力やその他の活動の通知を提供することです。libuvは、タイマー、ノンブロッキングのネットワーク対応、非同期ファイルシステムアクセス、子プロセスなどの基本的なユーティリティを提供します。</p>&#10;<section id="event-loops">&#10;<h2>イベントループ<a class="headerlink" href="#event-loops" title="この見出しへの固定リンク">¶</a></h2>&#10;<p>イベント駆動プログラミングでは、アプリケーションは特定のイベントへの関心を表明し、そのイベントが起きたときに応答します。オペレーティングシステムからイベントを集めたり、他のイベント発生源を監視したりする役割はlibuvが担います。利用者は、イベント発生時に呼び出されるコールバックを登録できます。イベントループは通常、<em>ずっと</em>動き続けます。疑似コードで表すと、次のようになります:</p>&#10;<div class="highlight-python notranslate"><div class="highlight"><pre><span></span><span class="k">while</span> <span class="n">there</span> <span class="n">are</span> <span class="n">still</span> <span class="n">events</span> <span class="n">to</span> <span class="n">process</span><span class="p">:</span>&#10;    <span class="n">e</span> <span class="o">=</span> <span class="n">get</span> <span class="n">the</span> <span class="nb">next</span> <span class="n">event</span>&#10;    <span class="k">if</span> <span class="n">there</span> <span class="ow">is</span> <span class="n">a</span> <span class="n">callback</span> <span class="n">associated</span> <span class="k">with</span> <span class="n">e</span><span class="p">:</span>&#10;        <span class="n">call</span> <span class="n">the</span> <span class="n">callback</span>&#10;</pre></div>&#10;</div>&#10;<p>イベントの例を挙げると、次のようなものがあります:</p>&#10;<ul class="simple">&#10;<li><p>ファイルに書き込む準備ができた</p></li>&#10;<li><p>ソケットに読み取り可能なデータがある</p></li>&#10;<li><p>タイマーの時間が経過した</p></li>&#10;</ul>&#10;<p>このイベントループは、<code class="docutils literal notranslate"><span class="pre">uv&#95;run()</span></code>にまとめられています。これはlibuvを使う際の中心となる関数です。</p>&#10;<p>システムプログラムで最もよく行うのは、大量の数値計算よりも、入力と出力の処理です。従来の入出力関数（<code class="docutils literal notranslate"><span class="pre">read</span></code>、<code class="docutils literal notranslate"><span class="pre">fprintf</span></code>など）の問題は、これらが<strong>ブロッキング</strong>であることです。ハードディスクへの実際の書き込みやネットワークからの読み取りは、プロセッサーの速度に比べて非常に長い時間がかかります。処理が終わるまで関数が戻らないため、その間、プログラムは何もしていません。高い性能が必要なプログラムでは、他の活動や入出力操作まで待たされることが大きな障害になります。</p>&#10;<p>標準的な解決策の1つは、スレッドを使うことです。それぞれのブロッキング入出力操作を、別のスレッド（またはスレッドプール）で開始します。そのスレッドでブロッキング関数が呼び出されると、オペレーティングシステムは、実際にCPUを必要とする別のスレッドを実行するようスケジュールできます。</p>&#10;<p>libuvが採るのは、別の方式である<strong>非同期・ノンブロッキング</strong>方式です。現代のほとんどのオペレーティングシステムは、イベント通知の仕組みを提供しています。たとえば、ソケットに対する通常の<code class="docutils literal notranslate"><span class="pre">read</span></code>呼び出しは、送信側が実際に何かを送るまでブロックします。その代わりに、アプリケーションは、ソケットを監視してイベント通知をキューに入れるようオペレーティングシステムに要求できます。アプリケーションは、都合のよいときにイベントを調べ、データを取得できます（その前に数値計算を行って、プロセッサーを最大限に活用することもできます）。これが<strong>非同期</strong>なのは、アプリケーションがある時点で関心を表明し、時間的・空間的に別の時点でデータを使うからです。また、<strong>ノンブロッキング</strong>なのは、アプリケーションのプロセスが自由に他の作業を行えたからです。オペレーティングシステムのイベントをlibuvのイベントの1つとして扱えるため、この方式はlibuvのイベントループ方式によく適合します。ノンブロッキングであることにより、他のイベントも到着する速さに合わせて処理し続けられます<a class="footnote-reference brackets" href="#id2" id="id1" role="doc-noteref"><span class="fn-bracket">[</span>1<span class="fn-bracket">]</span></a>。</p>&#10;<div class="admonition note">&#10;<p class="admonition-title">注記</p>&#10;<p>入出力をバックグラウンドでどのように実行するかは、ここでは問題にしません。ただし、スレッドをプロセッサーの基本単位とするハードウェアの動作方式により、libuvやオペレーティングシステムは通常、バックグラウンドのスレッド・作業スレッドやポーリングを使って、ノンブロッキングで作業を行います。</p>&#10;</div>&#10;<p>libuvの主要開発者の1人であるBert Belderが、libuvのアーキテクチャーとその背景を説明する短い動画を公開しています。libuvを使ったことがない方には、短時間で役立つ内容を見ることができます。</p>&#10;<p>libuvのイベントループについては、<a class="reference external" href="https://docs.libuv.org/en/v1.x/design.html#the-i-o-loop">文書</a>で、より詳しく説明しています。</p>&#10;<iframe allowfullscreen="" frameborder="0" height="315"
