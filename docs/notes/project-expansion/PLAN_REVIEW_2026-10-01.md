# 公式文書プロジェクト継続運用計画のレビュー記録

実施日: 2026-10-01。対象は [公式文書プロジェクトの継続追加と更新の運用計画](../../plans/CONTINUOUS_DOCUMENT_PROJECT_EXPANSION_PLAN.md)。草稿を保存した後、同じCodexが別の確認パスで1回レビューし、下記を本文へ反映した。別担当者や人手によるレビューではない。

## レビュー結果と反映内容

| 問題 | 修正 |
| --- | --- |
| 初期実証3件と公開待ち2件上限が衝突する | 公開指示がなければ2件で暫定評価し、3件目は公開待ち枠が空いてから着手する。未実施を完了にしない |
| プロジェクト数の増加で更新確認が作業を圧迫する | 期限超過順、最大10件・15分の目安、未確認分の繰り越し、遅延報告を追加 |
| 公開待ちの間に候補だけが増え続ける | eligibleの待機枠を3件に制限し、詳細調査の補充条件を明確化 |
| 公開待ちを状態名で回避できる | verifiedかつProduction未反映の新規・更新作業IDで集計し、Preview済みも含める |
| 点数の根拠が不足したまま自動採用され得る | 採用前に証拠へ戻る別パスを追加し、70点と主要2項目の最低点を明確な条件にした |
| 実行モデル名が取得できるとは限らない | 設定値と実モデル確認の結果を区別し、確認不能を推測で埋めない |
| 正常経路だけでは再開や誤採用を検証できない | 権利unknown、重複、上限、レビュー失効、中断不整合、再生成の反復と失敗を検査対象に追加 |
| 7日という数値が自動巡回の保証に読める | 稼働時の期限判定と定期起動を分離。スケジュール未登録と未稼働中の扱いを明記 |

## リポジトリとの照合

- 既存の取得・定本化・翻訳ガイド、GLFW・Luaの振り返りから、固定入力、原文保全、逐次翻訳、進捗の単一正本を継承した。
- `templates/docs-site/` とプロジェクト作成器の実装を確認した。作成器はlanding設定も変更するため、専用作業場所と統合時の検査を計画に含めた。
- 安全出力・一括出力の実装を確認し、汎用変換器を新規作成する前提を避けた。
- Pages workflowには特定ブランチのpushからPreviewを公開する経路があるため、ローカル検証と外部公開を区別した。
- ユーザーの採用済み方針に従い、通常の候補選定と翻訳はCodexが行う。古い文書の人手レビュー表現を、そのまま完了状態へ流用しない。

## 検証と対象外

計画と本記録をremarkで解析し、各文書の単一H1、コードフェンスの対応、末尾空白がないこと、相対リンク10件の存在、記載した既存コマンドのpackage.json登録を確認した。今回作成したのはこの2文書だけであり、別プロセスのAwesome作業、共通索引、package.json、アプリ、配信設定は変更していない。文書の実行計画であるため、候補採用、コード実装、アプリビルド、定期実行設定、外部公開は未実施。

実行後に確定する値は、候補の実測規模、処理工数、保守負荷、変換器ごとの適合性である。件数・採点・時間の初期値は、根拠なく処理性能を保証する数値として扱わず、初期実証の結果で調整する。
