# ADR-0006: デプロイ成果物を予算管理し圧縮を配信基盤へ委ねる

- ステータス: 承認
- 日付: 2026-08-11
- 提案者: リポジトリ管理者
- 承認者: リポジトリ管理者
- 置換対象: ADR-0004のgzip生成物に関する決定
- 置換元: なし

## 背景

Cloudflare PagesとWorkers Static Assetsにはデプロイ単位のファイル数上限がある。libxは通常JSONとgzip済みJSONを両方生成し、さらに同じサイドバーを二つの公開パスへコピーしていた。クライアントは通常JSONだけを要求し、Pagesは配信時にGzipまたはBrotliを適用できる。

## 決定

デプロイ成果物の件数、最大ファイルサイズ、容量をCIで予算管理する。実効上限を確認できるまでは20,000件を基準に、60%で警告、90%で停止する。

サイドバーは通常JSONだけを生成・追跡し、事前gzip版は廃止する。圧縮はCloudflareの配信機能へ委ねる。同じサイドバーを複数の公開パスへ複製しない。

## 判断理由

利用されないファイルを減らすと、上限到達を遅らせ、生成・追跡・アップロードの負荷も減る。配信基盤のコンテンツネゴシエーションを使う方が、利用者ごとの対応形式を選択できる。上限より前にCIを止めることで、公開時に初めて失敗する事態を避けられる。

## 検討した代替案

- gzip版を残す案は、直接参照がなくファイル数を増やすため採用しない。
- 上限到達時だけ対応する案は、デプロイ不能になるまで増加傾向を検出できないため採用しない。
- 直ちにR2へ全面移行する案は、現在の規模に対して運用複雑性が大きいため採用しない。

## 影響

`.json.gz`はリポジトリから削除される。Cloudflare以外へ配信する場合も、配信サーバー側の圧縮を有効にする。Pagesの実効上限を確認した後は、予算の基準値を20,000から100,000へ変更できる。

## 検証方法

- サイドバー生成後に`.json.gz`が存在しないことを確認する。
- 統合出力に二重配置がないことを確認する。
- 小さいfixtureで件数、警告、停止、最大サイズ検査をテストする。
- 統合ビルド後にデプロイ成果物検査を実行する。
