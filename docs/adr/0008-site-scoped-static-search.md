# ADR-0008: サイト・版・言語別の遅延読込静的検索を採用する

- ステータス: 承認
- 日付: 2026-08-11
- 提案者: リポジトリ管理者
- 承認者: リポジトリ管理者
- 置換対象: なし
- 置換元: なし

## 背景

LuaやGLFWの長いリファレンスでは、サイドバーだけでAPIシンボルへ到達しにくい。検索のために全言語・全版の索引や検索ライブラリを初期表示で読み込むと、表示速度、ファイル数、選択的ビルドの原則を損なう。

## 決定

- ビルド前に、対象サイトのコンテンツだけから版・言語ごとのJSON索引を1ファイル生成する。
- 索引にはページtitle、description、見出し、明示アンカー、API識別子、検索用本文を格納する。
- 検索UIの起動時まで索引を取得せず、検索本体も動的importする。
- 評価順は、API識別子完全一致、title／見出し一致、description／本文一致とする。
- 結果URLは現在のサイト、版、言語内だけに限定する。
- 初期予算は、1索引あたり非圧縮2 MiB、生成時間はサイト単位5秒とする。超過時は本文の語彙索引化またはサイト分割を再検討する。

## 判断理由

外部サービスや大きな依存を使わず、静的配信とno-JSの通常ナビゲーションを維持できる。1版・1言語につき1ファイルなのでPagesのファイル数への影響を予測でき、選択的ビルドの境界とも一致する。

## 検討した代替案

- 全文をページごとのファイルで格納する案は、ファイル数を増やすため採用しない。
- Pagefind等の外部検索ライブラリは、高機能だが出力ファイル数と依存が増えるため現在規模では採用しない。
- 外部検索サービスは、ネットワーク障害、プライバシー、運用設定を増やすため採用しない。
- 語彙の転置索引は容量を削減できるが、日本語tokenizationと更新実装が複雑なため、予算超過までは採用しない。

## 影響

検索索引ファイルが版・言語数だけ増える。検索操作時には該当する1ファイルの転送が発生する。検索が失敗してもサイドバー、目次、通常リンクは影響を受けない。

## 移行方法

全配信サイトとテンプレートのprebuildへ共通生成スクリプトを追加する。ロールバック時は検索UIと生成コマンドを外し、通常ナビゲーションを維持する。

## 検証方法

- Luaで`lua_absindex`、章見出し、日本語本文から正しいURLまたはアンカーを得る。
- 初期ネットワークに検索索引が含まれず、検索起動後に現在の版・言語の1索引だけを取得する。
- 索引件数、容量、生成時間を品質レポートへ記録する。
- 選択的ビルドが対象外サイトの索引を変更しないことを検査する。
