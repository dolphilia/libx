# ADR-0010: 文書出典とライセンス帰属を本文最下部へ統合する

- ステータス: 承認
- 日付: 2026-08-19
- 提案者: リポジトリ管理者
- 承認者: リポジトリ管理者
- 置換対象: なし
- 置換元: なし

## 背景

外部文書を扱うサイトでは、`SourceStatus`が本文冒頭へ出典・上流版・翻訳状態を表示し、`LicenseAttribution`がサイト共通フッターへ帰属文・原文・ライセンスを表示していた。同じ設定を別コンポーネントが解釈するため情報とリンクが重複し、ページ固有の出典指定は冒頭にしか反映されなかった。サイトフッター方式は入口や404にも文書単位の帰属を表示し得る。

GLFWとLuaでは全184ページがサイト既定値と同じ`licenseSource`を重複記述し、インポータと翻訳検証もその重複を必須としていた。GLFWでは同じ移植通知をさらに本文冒頭へ手書きしていた。

## 決定

出典、上流版、定本／翻訳状態、帰属文、原文、ライセンスを`DocumentProvenance`へ統合し、文書本文とページネーションの後、`article`の最後へ表示する。

`project.config.jsonc`の`licensing`を正本とし、ページの`licenseSource`は`defaultSource`と異なる場合だけ指定する。ページ単位の帰属非表示と自由記述による置換は提供しない。出典参照が不正な場合は表示を省略せず、検査またはビルドを失敗させる。

## 判断理由

- 本文の読み始めを出典パネルと定型通知で押し下げない。
- 文書単位の情報を本文幅と意味的な`aside`へまとめられる。
- 出典と法的帰属が必ず同じソース設定を参照する。
- 入口と404から文書単位の表示を分離できる。
- 既定値継承により大量ページのFrontmatterと翻訳差分を減らせる。
- 静的HTML、no-JS、印刷、多言語で同じ情報を維持できる。

## 検討した代替案

### 冒頭表示とサイトフッター表示を維持する

- 利点: 変更が小さく、出典状態を読む前に確認できる。
- 欠点: 重複、本文開始位置の後退、ページ固有設定の不一致が残る。
- 採用しなかった理由: 表示責務とデータ解決が二重のままになるため。

### 冒頭表示だけを最下部へ移し、ライセンスフッターを残す

- 利点: 既存コンポーネントを再利用できる。
- 欠点: 同じ出典へのリンクと翻訳情報が引き続き二重になる。
- 採用しなかった理由: 管理負担と不整合可能性を解消できないため。

### 文書本文へ通知を手書きする

- 利点: ページごとに自由な説明ができる。
- 欠点: 翻訳差分、更新漏れ、Markdown本文へのlibx固有情報混入が増える。
- 採用しなかった理由: 設定一元管理と移植可能な定本という原則に反するため。

## 影響

### 良い影響

- 文書冒頭が技術本文から始まる。
- 出典・翻訳・ライセンス情報が一か所で確認できる。
- 既定ソースの変更を設定ファイル一か所で反映できる。

### 悪い影響・トレードオフ

- 読者が出典情報を見るには文書末尾まで移動する必要がある。
- 旧コンポーネントを直接利用していたコードは移行が必要になる。

### 影響する範囲

- 正規ドキュメントレイアウトと全配信アプリ
- `@docs/ui`の公開コンポーネント
- Frontmatterスキーマ、インポータ、翻訳検証、執筆ガイド

## 移行方法

`SourceStatus`、`LicenseAttribution`、文書サイトのライセンス用`Footer`を撤去する。GLFWとLuaの定型通知および既定値と同じ`licenseSource`を削除し、インポータも同じ出力へ変更する。正規レイアウトから各アプリへ同期する。

## 検証方法

- 文書ページの`article`内に`DocumentProvenance`が1件だけあり、ページネーションより後にあることを検査する。
- 入口と404に文書情報パネルがないことを検査する。
- 英語定本、日本語翻訳、RTL、モバイル、印刷、no-JSで表示を確認する。
- 全runtime test、コンテンツ検査、全サイトビルド、統合ビルドを実行する。
