# Architecture Decision Records

このディレクトリには、libxの構造・互換性・運用へ継続的な影響を与える重要な決定を記録します。

## ADRを作成する対象

- URL・ルーティング構造
- 設定の正本と継承規則
- パッケージやサイトの責務境界
- ビルド・デプロイ・キャッシュ方式
- 公開API、互換性、廃止方針
- 性能・国際化・アクセシビリティの基準
- 複数の合理的な選択肢があり、後から判断理由を知る必要がある事項

通常の不具合修正、局所的なリファクタリング、原則から自明な変更にはADRは不要です。

## ファイル名

`NNNN-short-title.md` の形式を使用します。

- `NNNN`: 4桁の連番
- `short-title`: 英小文字とハイフンによる短い題名
- 最初の正式ADRは `0001-...md` とする

新しいADRは [0000-template.md](./0000-template.md) をコピーして作成します。

## ステータス

- `提案`: 検討・レビュー中
- `承認`: 採用され、現在有効
- `却下`: 検討したが採用しなかった
- `置換`: 新しいADRにより置き換えられた
- `廃止`: 決定が不要または無効になった

## 承認手順

1. 提案者がテンプレートからADRを作成し、ステータスを `提案` にする。
2. リポジトリ管理者が、正式原則との整合性、代替案、影響、移行・検証方法を確認する。
3. 必要な修正と議論を反映する。
4. 管理者の承認後、日付とステータスを `承認` に更新する。
5. 管理者が一人の場合も、判断理由と比較した代替案を記録したうえで自己承認してよい。

承認済みADRの決定内容を後から書き換えません。決定を変更する場合は新しいADRを作成し、旧ADRを `置換` または `廃止` にして、新旧文書を相互にリンクします。誤字やリンク切れなど、決定内容を変えない修正は既存ADRへ直接行って構いません。

## 原則との関係

すべてのADRは [libx コンセプト・方針・方向性・開発原則](../spec/PROJECT_PRINCIPLES.md) に従います。原則の例外を提案する場合は、例外が必要な理由、影響範囲、解消条件をADRに明記します。
