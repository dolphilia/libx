# ADR-0009: 正規テンプレートからドキュメントサイトのレイアウトを同期する

- ステータス: 承認
- 日付: 2026-08-11
- 提案者: リポジトリ管理者
- 承認者: リポジトリ管理者
- 置換対象: なし
- 置換元: なし

## 背景

`MainLayout.astro`と`DocLayout.astro`がテンプレートと4配信アプリへ複製され、メタデータ、本文クラス、i18n、目次などの修正を5回適用する必要があった。Astroレイアウトをそのまま共有パッケージへ移す案は、サイト固有CSS import、コンテンツcollection、slot転送をパッケージ境界へ持ち込み、変更範囲が大きい。

## 決定

`templates/docs-site/src/layouts/`をレイアウトの正本とする。共通同期スクリプトで`MainLayout.astro`と`DocLayout.astro`を全配信アプリへ決定的にコピーし、integrity checkで差異を失敗させる。

サイト固有のレイアウト差分は原則としてProps、slot、プロジェクト設定、共有CSSへ移す。例外が必要な場合は同期対象から外さず、正規テンプレート側へ一般化した拡張点を追加する。

## 判断理由

- 新規サイトが利用するテンプレート自体が正本なので、生成直後から同じ契約になる。
- AstroのコンテンツcollectionとサイトCSSを現在のアプリ境界に保てる。
- 修正はテンプレート1か所と同期コマンドで済み、反映漏れを自動検出できる。
- パッケージ化より小さい変更で、URLと生成HTMLの回帰リスクが低い。

## 検討した代替案

- `packages/ui`へAstroレイアウトを移す案は、物理的な複製をなくせるが、サイトCSSとcollection依存がUIパッケージへ流入するため採用しない。
- Astro layoutを多段合成する案は、slot転送とPropsが増え、各アプリの薄いwrapperが残るため採用しない。
- 手動で差分を監査する案は、すでに反映漏れが発生しており再現性がないため採用しない。

## 影響

配信アプリ内の2ファイルは生成・同期対象となり、直接編集しない。サイト固有差分は共有契約へ一般化する必要がある。同期後のファイルはリポジトリへ追跡し、個別サイトのビルドを単独で実行できる状態を維持する。

## 移行方法

テンプレート側へ現在の共通機能を統合し、同期スクリプトで4アプリを揃える。以後は`pnpm sync:layouts`を実行し、`pnpm check:integrity`で差異を検査する。ロールバック時はスクリプトと検査を外せるが、同期済みレイアウトは通常のソースとして動作し続ける。

## 検証方法

- 同期直後に全対象ファイルのbyte列が一致する。
- 1アプリの意図しない変更をfixtureで作ると`--check`が失敗する。
- テンプレート、Lua、GLFW、sample-docs、test-verificationをビルドする。
- 代表URLのtitle、canonical、言語・版切替、サイドバー、目次を比較する。
